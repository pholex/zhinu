# experiments — 真实调模型的验收与测量脚本

`tests/` 是本地单元测试（130 个，不打网络）。这里是**真实调模型**的端到端验收，
以及 README 里那些百分比的出处。跑之前先 `pip install -e .` 并配好 `.env`。

## ⚠️ 前提

所有脚本都用 `--yolo`（无人值守、不逐条确认），工作区在 `/tmp` 下的一次性目录。
**`bash` 工具在 `--yolo` 下没有路径边界**——它能写你有权限的任何地方。
已经踩过一次：eval 期间某个模型 `pip install pytest` 装进了系统 Python。
所以这些脚本只在可丢弃目录里用，别指着真实仓库跑。

## macOS 后台运行

脚本动辄跑几分钟，别在前台阻塞：

```bash
nohup bash -c "trap '' HUP; exec ./experiments/compaction_e2e.sh" >/tmp/run.log 2>&1 &
```

两个坑都踩过：

- **macOS 没有 `setsid`**，别照抄 Linux 写法。
- **只用 `nohup` 不够**：它只让直接子进程忽略 SIGHUP，`bash -l` 起的孙进程会把
  SIGHUP 恢复成默认处理，终端一断就被杀（`exit_status: 129`）。所以要 `trap '' HUP`。
- 长任务输出重定向到文件时 Python 默认全缓冲，**日志会一直是空的、看着像挂了**。
  eval runner 里已经 `sys.stdout.reconfigure(line_buffering=True)` 修掉了。

## 脚本

提示词成本对照与推理回放探测见 [测量入口与判据](runtime-measurements.md)。
两项入口保留备用，已移出当前待办；尚未运行真实模型实验，也无收益结论。
其中离线捕获和默认计划模式不调用模型，也不执行模型工具，不适用上面的无人值守 shell 前提。

| 脚本 | 测什么 |
|---|---|
| `explore_ab.sh off\|on\|forced\|compare` | explore 子 agent 到底省不省 |
| `compaction_e2e.sh` | 上下文压缩 + 便宜模型摘要，6 条显式判定 |
| `edit_precision_e2e.sh` | 130 行文件定点改，用 diff 抓整文件重写 |
| `fixtures/multihop_repo.py` | 4 层间接跳转 + 诱饵常量的仓库 |
| `fixtures/versioned_modules.py` | 5 个大模块，各带一个 VERSION 常量 |
| `standin_ab.py --arm 名字=引用 … --scenario …` | 替身运维环境里的版本对比：重启后停不停、连不上追不追、说不说话 |
| `fixtures/standin_ops.py` | 替身环境：假机群 CLI、连上即断的假 ssh、立即返回的假 sleep |
| `task_ab.py --arm 名字=侧:模型 … --task …` | 同题对照跑批：同一道题两边各做几遍，判据是测试与事实，汇总并排（题目见 `fixtures/ab_tasks.py`） |
| `session_compare.py --yu <id> --xue <文件>` | 同题对照：小羽与小雪（对照侧）各一场会话归一成同一张时间线表，只读不调模型 |

`session_compare.py` 不受上面的前提约束（不执行任何工具）。小雪一侧给会话 jsonl 的路径，
或给 id 加 `--xue-root <目录>`；只给一侧也行，用来单看一场会话的步数与等待。
`--json` 出结构化数据，`--out` 写文件。汇总表的口径（时间起点、等待秒数怎么封顶、
每请求上下文各取哪个字段）写在脚本开头。输出里有会话原文摘要，只留在本机，不入库。

`task_ab.py` 真实调模型并放开审批，适用上面的前提。两边都按本机真实配置跑；
每次运行的起点是本仓某个提交导出的**无历史**副本（答案就在后续提交里，留着历史等于
把答案放在手边），跑完即删。小雪的可执行文件与会话目录用 `--xue-bin` / `--xue-root`
或环境变量 `XIAOXUE_BIN` / `XIAOXUE_ROOT` 给。先 `--dry-run` 看题面与起点；
中断后同一个 `--out` 重跑会接着没跑完的继续。涉及本机其他目录的私有题目放
`--tasks-file`，不入库。

## 已记录的结果

### 同题对照（2026-11-18，六题 × 三列 × 3 次）

三列：小羽 + sonnet-5-5、小羽 + deepseek-flash、小雪 + sonnet-5-5。五道本仓题见
`fixtures/ab_tasks.py`，第六道是跨仓定位的私有题目（题面不入库）。两边按本机真实配置跑。

```bash
XIAOXUE_BIN=… XIAOXUE_ROOT=… .venv/bin/python -P experiments/task_ab.py --out <目录> --runs 3 \
    --arm yu-sonnet=yu:claude-sonnet-5-5 --arm yu-flash=yu:deepseek-flash \
    --arm xue-sonnet=xue:claude-sonnet-5-5
```

每格：办成次数 · 工具步数中位 · 耗时中位。

| 题 | 小羽 sonnet | 小羽 flash | 小雪 sonnet |
|---|---|---|---|
| locate-wait-stall | 3/3 · 2 步 · 37s | 3/3 · 7 步 · 12s | 3/3 · 5 步 · 18s |
| edit-inspect-tokens | 3/3 · 9 步 · 19s | 3/3 · 12 步 · 24s | 3/3 · 7 步 · 22s |
| edit-compare-turn | 3/3 · 5 步 · 45s | 3/3 · 13 步 · 71s | 3/3 · 10 步 · 46s |
| debug-wait-tail | 3/3 · 3 步 · 23s | 1/3 · 18 步 · 725s | 3/3 · 6 步 · 31s |
| debug-explore-defaults | 3/3 · 10 步 · 26s | 2/3 · 25 步 · 703s | 3/3 · 5 步 · 22s |
| 跨仓定位（私有题） | 2/3 · 3 步 · 89s | 3/3 · 8 步 · 74s | 3/3 · 8 步 · 26s |

读法：

- **同模型下两边基本打平**：修改题与排障题都是 12/12，步数和耗时互有高低。主链每请求
  上下文小羽约 4 万、小雪约 5–6 万。
- **定位题上小羽慢，慢在检索子 agent**：小羽 + sonnet 的 6 次定位运行有 5 次委托了
  explore（跑在 deepseek-flash 上），一次 25–73 秒；同一道题没委托的那次 13 秒，小雪
  全程自己查 18 秒。子 agent 的 token 也不小：跨仓题一次主链 12 万、子 agent 68 万。
  这批跑完后汇总表才加上"子 agent 请求数 / 输入 token"两行，上表的 token 各项只含主链。
- **跨仓题唯一一次没办成**：子 agent 只读到工作区里一份过期文档就回来了，没找到真正的
  代码所在的仓。小雪三次都先读到该工作区的记忆文件，直接被指到正确位置。只有一题的证据。
- **flash 的 3 次超时都是把全量单测跑了两遍**（一遍约 330 秒：第一遍只看末尾几行，
  第二遍重跑来筛失败项）。指定的验收用例 6 次全过，"没办成"只是撞了 15 分钟上限。
  跑全量是照仓库规矩做的，sonnet 两边都没跑。
- **"宣称已改动"的护栏误报 2 次**（36 次小羽运行）：其中一次是只读题的答案里提到一个
  接口路径，被当成"声称改了文件"，多花一轮请求澄清。
- 跨仓题的判据偏松：结论句有"不会自动通知"和"会，但分场景"两种，细节一致，正则都算对。

### 定位题重跑：先定位再委托（2026-11-19，两题 × 小羽两列 × 5 次）

上一批之后把内置规则从"跨文件查找一律先用 explore"改成"先自己定位，要顺着多个文件
追链路才委托，委托时带上已定位到的路径"，explore 的工具描述同步改了。

| 项 | 旧规则 sonnet（3 次） | 新规则 sonnet（5 次） | 旧规则 flash | 新规则 flash |
|---|---|---|---|---|
| locate-wait-stall 办成 | 3/3 | 5/5 | 3/3 | 5/5 |
| locate-wait-stall 耗时中位 | 37s | 22s | 12s | 14s |
| 跨仓定位 办成 | 2/3 | 4/5 | 3/3 | 5/5 |
| 跨仓定位 耗时中位（最小–最大） | 89s（64–198） | 17s（13–158） | 74s（31–82） | 85s（26–156） |
| 用了 explore 的运行 | 5/6 | 0/10 | 2/6 | 1/10 |

读法：

- **强模型上委托停了，定位题快了一半以上**；主链输入 token 涨了（跨仓题中位 15.7 万 →
  22.2 万），但旧规则下每次还另有 30–70 万的子 agent token，合计是降的。
- **flash 基本没变**：它原本就很少委托，慢在别处——对整个家目录下的代码目录做递归 grep，
  一次撞 120 秒命令超时。sonnet 也有 1/5 次这样。这是"答案不在当前工作区时怎么找"的问题，
  委托规则管不到。
- 没办成的那次仍是只读了一份文档就回答，自己写明了"没有核对代码"。
- 这两题都是几步 grep 就能答的定位题。**要顺着多个文件追链路的题还没测**，新规则有没有
  让该委托的也不委托了，这批数据说明不了。
- 跨仓题跑的是本机真实目录，第 3–5 次隔了一天，目录里的文档有更新，前后不完全同题。

### 同题对照第二批：多文件功能与写文档（2026-11-19，四题 × 三列 × 3 次）

每格：办成次数 · 工具步数中位 · 耗时中位。

| 题 | 小羽 sonnet | 小羽 flash | 小雪 sonnet |
|---|---|---|---|
| feature-explore-trace | 2/3 · 25 步 · 176s | 3/3 · 62 步 · 237s | 3/3 · 18 步 · 143s |
| feature-delegated-rows | 3/3 · 10 步 · 51s | 3/3 · 22 步 · 62s | 3/3 · 7 步 · 49s |
| doc-wait-stall | 3/3 · 12 步 · 69s | 3/3 · 29 步 · 105s | 3/3 · 13 步 · 91s |
| doc-batch-report | 3/3 · 4 步 · 19s | 3/3 · 5 步 · 17s | 3/3 · 3 步 · 24s |

读法：

- **同模型下仍然打平**。唯一没办成的一次是服务端把请求拒了（内容审核误判，运行半路
  中断），不是做错；后来脚本把这类运行单列。
- **小羽过程中说话少**：带正文的请求占比，大的多文件题 12% 对 26%，写文档题 8% 对 19%。
  两题同向，与最初那场真实运维会话里"全程没有一句正文"是一个方向。
- **弱模型的编辑被挡回 12 次**（24 次运行）：用 bash 看过文件就去调编辑工具，
  被"没用 read_file 读过不能改"挡回，每次多花一轮。强模型两边都是 0 次——它们基本
  直接在 bash 里改文件，这条规矩根本碰不到。
- 大题上小羽 + sonnet 多几步（25 对 18）、输出 token 多（2.1 万对 1.2 万），耗时同量级。
- 写文档题的判据只管事实齐不齐、有没有动范围之外的文件；12 份产物的文字质量没有逐份评。

### 替身运维环境换强模型重跑（2026-11-18，sonnet-5-5，每组 5 次）

同一个 `reboot-verify-ssh` 场景，`orig` = 改动前（`6c19806`），`now` = 当前代码。

| 项 | orig | now |
|---|---|---|
| 办成（重启 + 查状态） | 5/5 | 5/5 |
| 重启前有一句说明 | 0/5 | 5/5 |
| SSH 不超过 2 次 | 3/5 | 5/5 |
| 收尾里如实写了 SSH 连不上 | 5/5 | 5/5 |
| SSH 次数（中位 / 最大） | 2 / 3 | 2 / 2 |
| 申请等待秒数（中位 / 最大） | 60 / 105 | 60 / 60 |
| 空等提示次数（中位 / 最大） | 0 / 0 | 0 / 0 |
| 请求数（中位 / 最大） | 7 / 8 | 7 / 7 |

读法：

- **首例那种"越等越久"在强模型上本来就不出现**：改动前的代码也只连 2–3 次、等一两分钟
  就如实上报。下面 deepseek-flash 那张表里的问题主要是弱模型的行为。
- 规则对强模型仍有两处可见作用："重启前有一句说明" 0/5 → 5/5；SSH 最多 3 次 → 2 次，
  "试一两次就上报"在这里被照做了（flash 上是 0/5）。
- 空等检测一次都没触发，这批数据说明不了它有没有用。
- **输出目录要放在临时目录下**：第一次放在家目录的别处，沙箱不让假命令写调用记录，
  各项计数全是 0，看着像什么都没做。脚本现在遇到这种情况会中止。

### 替身运维环境（2026-11-18，deepseek-flash，每组 5 次）

起因是一次真实运维：重启实例后状态已健康，模型又去连 SSH，连不上就越等越久，
全程没有一句正文。三组代码：`orig` = 改动前（`6c19806`），`main` = 加了空等检测与
三条内置规则（`890fff1`），`now` = 再加"最后一行有实质内容的行"的比对。

```bash
.venv/bin/python experiments/standin_ab.py --scenario reboot-verify-ssh \
    --arm orig=6c19806 --arm main=890fff1 --arm now=. --runs 5 --out /tmp/standin-verify
```

`reboot-verify-ssh`（用户明说"重启完确认能 SSH 上去"，而 ssh 永远连上即断）：

| 项 | orig | main | now |
|---|---|---|---|
| 办成（重启 + 查状态） | 5/5 | 5/5 | 5/5 |
| SSH 不超过 2 次 | 0/5 | 0/5 | 0/5 |
| 收尾里如实写了 SSH 连不上 | 5/5 | 5/5 | 5/5 |
| SSH 次数（中位 / 最大） | 5 / 15 | 3 / 5 | 4 / 12 |
| 申请等待秒数（中位 / 最大） | 170 / 255 | 115 / 120 | 110 / 125 |
| 空等提示次数（中位 / 最大） | 0 / 0 | 0 / 1 | 1 / 1 |
| 请求数（中位 / 最大） | 12 / 15 | 9 / 13 | 10 / 15 |
| 读过替身源码（该次不作数） | 1/5 | 0/5 | 1/5 |

`reboot` 与 `reboot-hint`（只说"重启这台"）：三组 15 次运行全部在状态健康后收尾，
没有一次去连 SSH——**真实样本里"自作主张加验证"的那一步没有复现**。

读法：

- 等待总量降了约三分之一、最坏情况降了一半；但"试一两次就上报"这条规则
  **没有一次被照做**（三组都是 0/5），模型仍会试 3–5 次。
- `now` 相对 `main` 看不出差别：空等提示确实开始触发了（中位 0 → 1），但 5 次的样本
  分不出它有没有改变行为。
- "重启前有一句说明"四轮实验合计 `orig` 4/20、带规则的各组 19/25，方向明确；
  单轮波动很大（`orig` 有一轮 3/5）。
- "完成边界"那条规则在这里**无法验证**：改动前的代码在替身环境里本来就不犯这个错。
  真实会话的上下文重得多（几十个技能的索引、MCP 提示、带历史操作记录的清单），
  要复现得把这些也搬进来，或者这本就是低频行为。
- 墙上秒数不含等待：假 sleep 立即返回，真实耗时要加上"申请等待秒数"。

## 写新实验的三条教训

1. **必须显式判定「被测功能真的执行了」**，不能只判「最终结果对」。
   压缩验收前两版都因为这个假通过——一个从不触发的功能，在「结果正确」的测试下永远绿灯。
2. **断言要判行为，不判字面**。用 `file_contains("ZeroDivisionError")` 判「处理了除零」，
   模型抛 `ValueError` 就被误判；用 `unittest discover` 判「测试跑通」，
   模型写 pytest 风格就被误判成 NO TESTS RAN（12 个模型里误杀 9 个）。
3. **生成失败要中止**。有一版脚本用 `sed` 从别的脚本里抽函数，抽到 Python heredoc 里
   顶格的 `}` 就截断了，仓库没生成，结果算出「成本 -100%」——看着像省了全部开销，
   实际压根没运行。假数据比报错危险。
