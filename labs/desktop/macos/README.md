# 羽案 · macOS 桌面实验版

这是可双击启动的原生 `.app`：AppKit 管理窗口、菜单、目录选择与退出，
WKWebView 承载任务工作台。应用启动一个自己的 Python 服务进程，
界面和 API 使用同一个回环端口。无需手工开两个终端，也无需浏览器。

## 构建与打开

需要 macOS、Xcode Command Line Tools，以及已安装本仓库 `[serve]` 和 `httpx`
的 Python 3.11+ 环境。在 lab 工作树根目录运行：

```bash
/path/to/venv/bin/python labs/desktop/macos/build.py
open "labs/desktop/local-results/羽案.app"
```

可用 `--python /path/to/venv/bin/python` 显式选择运行环境。构建脚本只调用系统
Swift 编译器、复制运行源码并进行本机 ad-hoc 签名，不下载依赖，不修改核心包。
默认编译当前机器架构。每次修改源码后需退出应用并重新构建。

应用图标源文件为 `assets/AppIcon.png`，由用户提供的蓝色羽毛图适配而来。
构建时使用系统 `sips` 生成 16–1024 像素的普通与 Retina 图标，再由 `iconutil`
打包为 `AppIcon.icns`，写入应用资源并通过 `CFBundleIconFile` 注册。无需额外依赖。
图标处理说明和提示词见 [assets/README.md](assets/README.md)。

生成物忽略入库。默认 `build.py` 仍是使用外部虚拟环境的本机开发构建。
独立分发使用 [本地发布流程](DISTRIBUTION.md)：内置 Python 与桌面依赖，使用正式
签名、公证并生成 DMG。两种构建均复制源码到 `.app/Contents/Resources/runtime`。
当前没有应用内自动更新；新版本通过下载安装包更新。

应用中文名称为「羽案」。桌面版本使用 `x.x.x` 三段格式，当前 `0.13.3`，
统一声明于 `build.py` 的 `APP_VERSION`；应用包两项版本字段与“关于”窗口共用此值。
正式 Bundle ID 为 `click.openapi.xiaoyu`，默认开发构建仍使用原标识。
正式版首次启动复制旧版原生导航与模型选择偏好；可执行文件名与会话状态目录保持兼容。

## 使用与生命周期

- **首次打开**：显示羽毛标识和八家内置模型服务。检测应用继承的环境变量与当前用户同名钥匙串项；
  只显示来源与状态。首次配置自动启用应用环境或钥匙串中可读取的密钥；手动停用的选择会保留。
  检测到的钥匙串条目在配置页显示后自动尝试启用；需要时弹出系统授权，成功后自动勾选；输入框遮罩显示，保存使用系统钥匙串。
  已启用项在本机记住；首次启动已有可用凭据时直接进入默认工作台，没有凭据时保存后点击“开始使用”。启用不代表已验证额度或联网可用性。
  环境变量仅来自应用当前进程，不执行 shell 启动脚本；只在终端里 export 的变量未必由 Finder 启动的应用继承。
  默认读取 CLI 的环境变量、用户配置文件与受信工作目录配置；保留网关、自定义服务商及默认模型。配置页仅提供“开始使用”，本机密钥作为补充，不改写 CLI 文件。
- **工作台 → 打开示例工作台**：隔离临时目录、脚本模型、两个项目四个会话，无真实模型调用。
  示例中可看到完成成果、待审批、待答及失败。退出后清理示例目录；重启重新生成。
- **默认项目**：首次使用自动建立 `~/Documents/羽案/Default`，左侧显示 `Default`，新会话自动归入该项目，工作成果默认保存在此目录。无需先建项目或选择目录。
  手动选择过目录的用户继续使用其选择；旧版已有最近目录也保留，不搬迁历史会话。默认目录不能创建时提供更换目录入口，不覆盖同名文件。
- **选择工作目录**：目录选择器初始打开 `~/Documents/`，手动更改后记住所选位置；所选目录限定本次服务的 root。应用读取用户已有配置，
  保留 host 沙箱、default 模式与 ask 审批，不自动信任工作目录，也不启动模型任务。
  首次打开没有会话是正常情况：点击“新建任务”，在允许范围内创建会话后提交任务。
- **输入与模型**：桌面版自动连接所属本机后台，不要求输入服务地址或令牌。发送使用箭头图标，支持屏幕阅读器名称和悬停提示。
  新会话优先使用已保存的羽案选择，其次沿用 CLI 默认模型；尚未设置默认模型时使用已启用服务的首个可用模型；从输入框切换模型会自动保存到当前工作台偏好，后续新会话与重开继续使用。
  已有会话显示实际模型，模型选择不会改变正在执行的会话；保存失败会提示，模型不再可用时回退到可用清单第一项。
- **系统与用户技能**：服务启动时按核心规则自动发现 `~/.agents/skills`、核心用户配置目录下的 `skills` 与已安装插件技能。
  技能支持单项和整组开关，设置保存在应用级 `skill-settings.json`，多个工作目录共享，重启保留；
  禁用不删除文件。空闲对话更新索引，执行中的对话在下一轮应用。
  “插件”页自动读取清单，显示来源与发现状态；新会话自动加载索引，正文按需读取。
  `XIAOYU_SKILLS_DIR` 覆盖目录、`XIAOYU_ENABLE_SKILLS=0` 和停用名单继续生效，未受信项目技能不混入启动清单。
- **文件 → 新建工作台 / 打开文件夹 / 最近的工作台**：不同目录使用独立后台；同目录切回已有工作台，父子目录重叠时提示。
- **窗口 → 此工作台的新视图 / 恢复关闭的视图**：同工作台复用服务，主输入和表单草稿按稳定视图身份隔离；关闭的视图可恢复原草稿和回执。
- **关闭工作台与退出**：关闭单个视图先保存输入；关闭最后一个视图停止所属工作台服务，其他工作台继续。应用保留菜单，点击应用图标可重新打开空工作台。
  ⌘Q 先核对所有工作台的执行和待处理状态，保存所有视图后才停止各自后台。保存失败明确提示；服务停止最长等 6 秒，仅终止自己持有的进程。
- **恢复**：重启应用自动打开上次工作台并连接本机服务；恢复会话和草稿不重新提交任务。已有明确启用的自动化计划仍按原有调度规则运行。
  最近目录保留原视图身份，关闭的视图可从窗口菜单恢复。原生偏好不保存密钥、token 或服务地址。
- **工作台 → 重新连接界面 / ⌘R**：刷新界面，服务和会话保持原样。
- **工作台 → 重新启动此工作台服务…**：提示会打断任务，经确认后停止旧服务、启动新服务。
- **服务意外退出**：保留已打开的界面与输入，提示先复制未保存内容，再决定是否重启。界面进程退出只重载当前界面，不停止后台。
  应用异常退出时，服务收到控制管道 EOF 后自行停止；不按端口号杀进程。

没有托盘常驻、开机启动和休眠续跑。最小化窗口只隐藏窗口，服务仍在；关闭工作台停止其服务。
多工作台的状态归属和恢复规则见 [设计说明](../MULTI_WORKSPACE.md)。原生系统通知已接入，需在设置中明确申请权限；完成、失败、审批、问答和自动化
提醒可回到来源会话，系统是否展示仍受系统设置影响，暂无独立声音/静默时段设置。
与手工启动的 Web 版本不同，桌面退出会停止其管理的服务。

真实工作目录的会话状态保存在：

```text
~/Library/Application Support/Xiaoyu Desktop Lab/state/<工作目录路径的哈希>/
```

它和命令行 serve 的状态目录独立，避免接管或覆盖其他服务。工作区相同的第二个
桌面服务会被文件锁拦截；不同目录可独立启动。会话历史、标题与新记录的历轮结算
可恢复；实时事件缓冲不恢复，旧日志未记录的结算不会补造。
同目录的 `desktop.json` 保存草稿与待提交回执，独立于模型上下文；偏好、内容库、
项目元数据、连接和自动化分别使用应用状态文件。多窗口写入核对修订号，冲突不静默覆盖。
数据页备份仅覆盖声明的偏好/项目元数据，不包含全部会话、页面、成果或密钥。

## 连接边界

系统分配空闲端口并一直持有 socket，不先探测再抢占端口。只监听 `127.0.0.1`；
每次启动重新生成随机令牌，经父子进程私有管道交给窗口，不放入 URL、命令参数、
文件或访问日志。公开静态资源没有令牌；API 继续使用 serve 的鉴权。

工作台 WKWebView 使用非持久化数据容器；服务令牌仅用于当前页面内存里的请求。工作台只允许
当前服务页面导航；右侧外部网页使用另外的独立浏览容器，不能获得应用管理桥或服务令牌。成果的 Finder 定位桥只接收当前会话登记的成果 ID 与
所属轮次、七襄条目或斗巧候选，原生宿主向当前鉴权服务解析后复核路径；不接受任意路径，
不执行文件或命令。文本预览和差异经鉴权成果接口读取。
静态资源白名单、Host/Origin 校验、同源 CSP 与文本转义仍有效。
工作台读取会话发 GET；创建、任务、插话、停止、单次审批和回答经固定 POST 端点提交。
退出时的 abort 由拥有服务生命周期的宿主发起。鉴权的 `/desktop/state` 只管理本应用
草稿与回执，使用版本核对和原子替换，不接收任意文件路径。
退出应用或重启服务换端口后可恢复已保存的草稿与回执；恢复不会自动重发。
强制结束、断电或存储失败仍可能丢失尚未保存的最后修改，应先核对会话和工作文件。
服务端持久化任务键，已接收的原键不会因重启再次执行。

服务托管的宸枢成员继承主会话执行模式，审批带成员归属且仅允许单次决定；
文件写入守卫仍有效。未改变通用权限规则，本机当前用户及其进程不在额外隔离边界之内。

### 连接与调度生命周期

构建时一并复制同仓库 SDK 源码；开发入口显式加载该路径，无需另装不同版本 SDK。
配置与自动化记录保存于本工作目录的应用状态中，使用独占状态目录与原子写入。
每个会话的连接池独立，退出由 core 先停止执行再收尾连接；无法确认工作线程结束时
保留所有权到进程退出，不宣称已经安全关闭。重启只恢复公开配置，不恢复令牌或自动挂载。

系统浏览器授权桥只接收连接与授权请求 ID，在本机鉴权接口取得当前待授权地址后打开。
网页不能指定任意外部 URL；应用拒绝凭据 URL、非 HTTPS 的远程授权地址及过期授权。
凭据只驻服务内存，不进入 runtime.json、会话或页面草稿。真实账号需用户在浏览器完成授权。

自动化调度与此服务同生共灭。退出不会安装常驻任务，停机错过周期不补跑；再次打开先恢复
原触发记录，创建或提交结局未知则保留核对状态，不重新提交。运行详情通过原关联会话查看。


### 网页、终端与内容工作区（0.12.13–0.12.14）

右侧网页使用独立的非持久化 WKWebView，支持地址、导航、刷新和多个标签；只在用户
明确引用时将选中文本及网址送入输入草稿。禁止导航到工作台同源、下载与媒体采集，
没有模型读取或接管接口，不跨应用退出保留登录态。网页成果 HTML 则使用受限预览，
不执行脚本或加载远程资源；不能把它视为同等浏览器。

终端由应用服务创建真实 PTY，用户选择 zsh/bash，工作目录限定为所选会话允许范围。
用户输入直接以当前用户运行，与模型工具审批分开；不是新沙箱。关闭标签页可选择停止
或仅关闭视图，后者可在本服务内重新查看。退出应用收尾所管理终端，保留工作文件，
不承诺重启恢复活进程。渲染支持有限 VT 行为，复杂全屏应用应使用系统终端。

页面/项目资料、作品库、搜索和偏好由应用 API 提供；CLI 连接仍共用原执行者。
服务商设置只写核心用户配置，密钥不回显、不进入草稿/备份；与仅内存 OAuth 凭据不同，
需重启服务并核对有效配置。高级图像/办公编辑、完整标签布局恢复仍未实现。
0.13.0 的本地发布流程处理独立运行环境、签名、公证与安装包分发，不自动推送源码。

首次配置页测试：退出应用后，使用 `open "羽案.app" --args --setup` 显式打开配置页。此参数不删除密钥或工作台数据；正常启动仍自动进入工作台。
