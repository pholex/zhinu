## 打开 macOS 桌面实验版

原生窗口、目录选择器和菜单已经接入。应用自动启动本机服务并连接工作台；
每个工作目录使用独立服务，同工作台的多个视图共享服务；关闭工作台只停止自身服务，⌘Q 停止全部服务。构建、运行环境边界与生命周期见
[macOS 实验说明](macos/README.md)。默认开发构建使用本机 Python，独立交付构建内置 Python；

连接管理、自动化、应用草稿、偏好、内容库、项目元数据和 PTY 等应用接口由原生后端提供；下面独立启动的
通用 serve 不安装这些应用专属接口，相关页面会提示当前服务不支持。

## 插件管理

统一从“插件”进入，分为“技能”和“连接器”；“已添加”管理现有能力，“发现”提供添加入口。
技能支持搜索、查看说明和在对话中使用；连接器目前支持远程 HTTP 与本机 stdio MCP 服务，
区分保存配置和连接到当前会话。添加 MCP 使用独立表单，按 STDIO/HTTP 切换字段；
STDIO 可配置逐项参数、环境变量、显式传递的变量名及工作目录；流式 HTTP 可配置 URL、
Bearer 令牌环境变量、请求头及环境变量请求头。高级设置默认折叠，返回列表保留未完成输入，取消清除输入。
直接填写的值保存在本机配置及输入草稿；变量引用只保存名称，在连接时从应用环境读取值。
变量须在启动应用前设置；已连接后修改变量，需要断开并重新连接。配置文件仅当前用户可读。
新版本使用 connections-v2.json，首次沿用旧清单，保存时保留旧文件供回滚；新配置不回写旧版。
技能添加沿用本机目录与扩展包安装方式，暂未接入在线目录。
CLI/API 连接器尚未实现，后续仍归入连接器，不增加顶层类型。

## 启动 Web 工作台

以下命令从本分支的工作树根目录执行。`python` 应指向已安装本仓库 `[serve]`
可选依赖的虚拟环境；静态界面服务器本身只用 Python 标准库，浏览器端不需要构建。

先启动真实服务。工作目录须存在；两个项目必须位于同一服务 root 之下：

```bash
PYTHONPATH="$PWD" python -P -m xiaoyu serve \
  --workspace /path/to/projects --environment host \
  --cors-origin http://127.0.0.1:8421
```

另开终端启动界面：

```bash
python labs/desktop/server.py
```

打开 `http://127.0.0.1:8421`，连接 `http://127.0.0.1:8420`。服务若配置了 token，
在界面填写同一个令牌；令牌仅留在页面内存，不写入 URL、浏览器存储或日志。
断开时清空数据与凭据；刷新页面后手动重新连接。

如果修改界面端口，服务的 `--cors-origin` 也要对应修改。界面只连接显式本机
HTTP 地址，直接消费服务既有鉴权与来源白名单，不代理请求，不扩大服务监听范围。
读取走 GET，创建、任务、插话、停止、审批和回答走明确的 POST 白名单。
关闭页面或停止静态服务器不会停止独立的 serve。使用本分支服务并保持默认持久化；
旧服务或 `--no-persist` 连接仍可查看，操作按钮禁用。

### 无模型费用的浏览器验证

本机没有现成服务会话时，可以运行脚本模型夹具。除 `[serve]` 外需测试依赖 `httpx`：

```bash
PYTHONPATH="$PWD" python -P -m labs.desktop.demo
```

仍使用上面的静态服务器，打开 `http://127.0.0.1:8421/?fixture=1`，点击连接。
页面明确标记为脚本模型验证，默认连接端口 18420。夹具使用真实 serve、真实
审批和问答状态机，在隔离临时目录生成两个项目、四个会话：完成并交付文件、
等待审批、等待回答、执行失败。完成会话中包含真实七襄工具产生的两项检查结果，
另有一份正常关闭的 CLI 示例历史供查看与分支。不会读取真实模型配置或调用真实模型。

输出格式问题，回答后可再次继续。拒绝或停止不会批准写入。脚本只用于验证交互，
不会根据自然语言改变固定执行内容。Ctrl-C 停止夹具后会打断其挂起任务并清理临时目录。

### 宸枢协作看板与成员控制

按会话查看宸枢运行时的结构化快照：任务状态、scope、依赖、所属成员、工作分支与
工作树、成员模型与交接、发现、评审和最近活动。任务标记完成、成员可靠结算与代码
合并分别展示；评审显示提交时的 commit，不将历史 clean 判定显示为当前可合并。

快照由实际核心操作产生，后台成员在父轮结束后仍可更新看板。当前进程的运行成员
可以接收补充消息，或单独请求停止。操作绑定看板、成员和本次运行 ID；同名成员重新
启动后，旧请求不会作用到新运行。停止主轮只影响总枢，不表示后台成员已停止。

消息回执区分已排队、已进入成员上下文和结束前未接纳；进入上下文不等于任务已完成。
停止请求与实际停止分别呈现，不删除工作树、分支、已写文件或档案。成员草稿分别保存，
新一代运行不自动继承旧草稿。响应丢失可用原键核对；重启后不自动重发或唤醒成员。

服务托管的成员继承主会话执行模式，工具仍经过既有权限策略；需要审批时展示成员、
任务、工作目录与运行身份，只支持单次允许或拒绝。build 成员的文件写入守卫先于
宿主批准且在实际工具执行处再次核对；这不等于新增了完整文件系统沙箱。独立 CLI
成员保留原行为。GUI 已支持预览后新建/明确采用协作、规划任务、派遣/续跑成员、
检查差异、受控合并及独立整队清理。清理不是停止：活跃、脏或未知工作树阻止整次操作，
不提供强制清理；保留分支和档案，失败保留真实路径。

服务重启后保留历史快照；先前未结算的成员显示运行状态未知，已结算交接仍保留。
读取看板不会启动、收养或接管工作区中的宸枢。快照有条目与正文上限，截断、发布或
保存失败、旧数据缺口均有说明。此前未记录的旧评审和发现不会从文本报告推测补造。

### 斗巧候选比较与人工采纳

在会话中选择已加载的规格、共同任务、评判标准、2–6 个模型席位和判官模型，
核对预览后直接执行。模型可重复，以比较同一模型的不同尝试。候选使用既有审批、
能力范围与工作区隔离；执行中支持停止，普通输入框保留草稿，不能向候选批次插话。

候选答案、完整/部分/失败状态、成果和交付差异并排显示。判官推荐与人工采纳分别
记录：只能选择可靠结算中已完成的候选，改选保留理由和历史。采纳不会合并候选文件。
请求先保存回执再发送；断线后原键重试、服务重启恢复都不会重复执行或重复记录采纳。

已选方案可生成新的普通任务草稿，引用候选已保存正文、来源与用户补充要求；截断正文
有明确提示。已有不同草稿时选择追加或替换，不自动发送、不恢复候选子任务上下文。
同一会话最多显示最近 64 场比选，最多保存 1000 次采纳；已保存回执不因视图淘汰失效。

### CLI 历史与协作任务表

本机全部标准终端会话与应用会话出现在同一份清单里，不限于当前工作台的目录（工作目录已不存在的除外）。
属于其他目录的会话在标签处显示目录名，可以查看正文；状态条提供“在该目录的工作台中打开”，
继续与分支要到那个目录的工作台里做——每个工作台仍只在自己的目录范围内执行。
同一目录范围内的：“最近”与搜索结果按时间
合并，来源用“终端”标签区分，被终端占用的标“使用中”；“更多 → Xiaoyu CLI 会话”保留完整
分页列表。打开一条终端会话先看到原始正文，查看不取得它的写锁；正文下方的状态条给出当下
能做的事：

- **在这里继续**：来源已正常结束且无人占用时，羽案取得它的写锁，接着往同一份历史写
  （与具名会话续写同一条路，不复制）。继续期间终端打不开这场会话；在羽案关闭它即交还。
  这场会话在清单里只出现一次，带“终端”标签。删除它只交还，不删除终端那份历史。
- **已在终端中打开**：来源被终端占用时正文照常可读，状态条提供“重试”（对方结束后即可继续）
  与“另开分支”。分支只在来源停在回合边界时可用；轮中会说明原因。
- **另开分支**：创建独立的羽案会话并记录来源，保留原日志；提交前核对来源版本。

损坏或没有可靠结束记录的来源只能查看。分支复制当前有效上下文，清空或压缩前的审计正文
不重新送给模型。普通 CLI `resume` 仍复制历史到新文件；`xiaoyu connect` 仍是两端共用原执行服务。
继续与分支都不继承源授权、模型配置秘密或活进程，也不隔离或回滚工作目录里的文件。

任务内使用七襄后显示批次与逐项状态、模型和交接结果，支持分页与展开。
状态来自内核结构化事件；已结算结果保存在会话日志，重启后仍可查看。
未结算项在重启后标为中断，不假定成功；最多显示最近 64 批，长交接明确标注截断。
“新建七襄”从会话实际加载的织手中选择，填写任务模板及 2–64 项任务，预览展开后的
指令再明确提交。选择已结算批次的条目并补充要求，可创建关联来源的新批次；
旧批次与旧结果保留。存档、原模型、工作目录及上下文需完整可用；丢失的隔离工作树
不能冒充原环境续跑。单项停止和运行中定向补充已在 0.9.0 接入，绑定精确执行身份。

直接操作走既有工具执行、权限及审批流程；预览不等于允许执行。
两类表单草稿独立保存；提交回执丢失可保留原请求与幂等键重试，重启后已记录请求不重跑。

“检查成果”按登记的成果 ID 读取文本、Markdown 和代码，显示交付时快照与当前文件，
有改前快照才显示本次差异。每份文本快照上限 64 KiB、每轮有总容量上限，二进制、过大文件、
旧日志和缺失基线明确说明不可预览的内容；这不是完整版本库。原生窗口可在 Finder 定位
仍存在且安全可读的成果文件。不会把交付后修改的内容标成原交付，也不会执行文件。

原生 HTML / CSS / ES modules，位于 `web/`；`server.py` 只提供白名单内的静态资源，
不会将仓库或工作目录暴露为文件服务器。主要能力：

- 侧栏工作台、待处理、执行中、可折叠项目与最近会话；系统字体与系统明暗主题。
- 按工作目录分组，按状态及会话标题、id、路径或模型筛选；支持搜索与侧栏快捷键。
- 新建会话与提交任务，流式展示正文；运行中插话、停止本轮，完成后继续。
- 审批展示工具和完整参数，已有理由随事件展示；未提供时明确说明。支持单次允许与拒绝。
- 问题支持选项、自由文字和明确跳过；已排队与模型已接纳分别展示，空闲时由用户明确继续。
- 将失败、审批、待答、重启中断和预算用尽单独呈现；审批等待不计入“执行中”。
- 空闲会话收到需要继续处理的后台结果时，列入待处理；页面不会自动唤醒模型。
- 每次读取会话列表和持久化问题，问题查询失败显示“状态未知”，不误报完成。
- 分页读取原始用户与助手历史正文，以及历轮结算、文件路径、字节数和 SHA-256。
- 标题、结算和成果记录重启后恢复；旧日志、存档失败或损坏记录明确提示缺口。
- 实时进度仍按游标查看最近 200 条事件，与持久化历史按执行边界合并。
- 连接失败时保留并标注旧数据；切换连接时取消旧请求并清空旧会话。
- 模型正文、路径、工具参数等外部内容作为文本展示，不执行 HTML。

历史正文来自受控服务接口，不直接读取日志文件；模型压缩后的上下文不冒充原始历史。
会话消息中的图形附件预览与下载仍待后续；登记成果已有受限 PNG/JPEG 预览。旧日志中的轮次结算与成果可能不完整，
升级不会补造此前未记录的结果。历史读取不包含完整工具详情或图形附件预览。

### 提交与重试边界

- 原生应用将草稿、待提交原文和幂等键保存在工作目录对应的应用状态文件，确认保存后才提交；
  Web 独立入口仍使用当前标签页 `sessionStorage`。重复点击不并发发送。
- 页面刷新或断线后不会自动重发。创建、任务、七襄、斗巧、人工采纳和回答的未知回执可保留原键重试；
  插话和审批的未知回执要求先核对状态，不提供盲重试。
- 停止和插话绑定服务实例及轮次。旧停止请求不能打断新服务或下一轮。
- 任务小回执随服务会话清单保存；结果被淘汰或服务重启后，原键只会提示已记录，不会重跑。
- 原生应用状态不包含连接令牌，服务换端口后仍可读取；恢复不会自动提交。
  正常退出、刷新和重启服务前等待草稿保存；保存失败会明确提示。
  Web 标签页存储不保证关闭标签页后的恢复。服务端回执仍随会话保留；
  删除会话或删除状态目录后失效。
- 原生多窗口共享应用元数据，并对冲突保留本地输入、要求核对；不自动合并同时修改的草稿。
  不承诺断电级持久化或自动恢复执行。服务重启后在途任务必须人工核对。

## 第一条使用路径

用户打开工作台，按工作目录找到会话，提交任务；离开页面后重新打开，能知道
哪些会话仍在执行、哪些需要回答或审批、哪些已完成或失败。处理一个待办后，
能检查对应会话的结果和文件产物，再决定是否继续。

项目以稳定 ID 组织会话，可不关联文件夹，也可关联多个文件夹并指定一个主文件夹。
新对话从主文件夹开始，已有对话保留创建时的工作范围；重命名或切换主文件夹不会改变项目身份。
应用元数据另存项目说明、指令、文本资料和作品引用，未发送输入按工作台、窗口与项目隔离。
服务只执行自己持有写锁的会话；终端会话须由用户明确选择“在这里继续”，正在终端中运行的不会被接管。

## 分阶段交付

### P0：先看清已有工作

- 连接一个本机 serve 实例，显示真实的连接状态与错误。
- 按工作目录列出会话，展示运行、审批、待答、完成、打断和失败状态。
- 显示当前会话的执行事件、最近结果与文件产物清单。
- 刷新或重连后重新读取权威状态；事件缺失时明确标识缺口。
- 无数据、服务不可达、请求失败、会话消失均有可操作的反馈。

验收：用户可找到一个待处理会话和一个已完成会话，读到准确状态和产物路径；
不依赖演示数据维持界面，页面刷新不发起模型执行。

### P1：完成一次工作闭环（已实现）

- 在服务允许的工作区内建立会话，通过 `prompt_async` 提交任务。
- 支持运行中插话、按轮次停止和完成后的继续。
- 展示审批的工具、参数和理由，支持单次允许与拒绝。
- 展示持久化问题，支持回答及提交状态；区分已排队和模型已接纳。
- 提交响应不确定时保留原幂等键，避免用户重试造成重复任务。

验收：使用脚本模型走完提交、执行、审批或待答、完成、查看产物的真实服务链路；
覆盖拒绝、失败、重复点击、断线和服务重启。再使用真实任务做日常试用。

### P2：决定是否继续投入

连续至少五个工作日，在至少两个真实项目中使用；记录实际任务，不填虚构指标。
比较工作台与原有终端路径：

| 观察 | 记录方法 |
|---|---|
| 找到需要介入的会话是否更快 | 对相似任务记录定位耗时与操作数 |
| 审批、问题或失败是否被遗漏 | 记录发生次数、发现方式与影响 |
| 找到并检查成果是否更容易 | 记录定位耗时及退回终端的原因 |
| 用户是否主动持续使用 | 每日记录主动打开的场景及放弃原因 |

出现持续收益时，再提出桌面分发与常驻范围；如果主要问题仍是内核执行质量、接口不足，
或工作台没有减少操作成本，则缩小范围或暂停实验。不能用截图完成度替代产品验证。

## 已有接口与需要确认的缺口

以下按本分支的文档及服务实现核对；服务增量是创建回执、任务回执持久化和实例校验。

| 需求 | 已有入口 | 使用边界 |
|---|---|---|
| 会话列表与创建 | `GET /session`、`POST /session` | 工作区必须符合服务端限制；终端会话经 `adopt_from` 明确原地继续 |
| 状态与最近结果 | `GET /session/{id}/status` | 不能把 idle 一律显示为成功；保留失败、预算与重启中断语义 |
| 事件流 | `/session/{id}/events`、`/events/stream` | 使用游标；识别缓冲丢弃、重启缺口和字段截断 |
| 提交、插话、停止 | `prompt_async`、`steer`、`abort` | 提交使用幂等键；停止绑定轮次，避免误伤下一轮 |
| 审批 | `GET/POST /session/{id}/permissions` | 权限判定留在内核，前端回传用户决定 |
| 持久化待答 | `/session/{id}/questions` 及 answers 端点 | 创建时显式开启；回答空闲会话不会自动启动模型 |
| 历史正文与结算 | `GET /session/{id}/history`、`GET /session/{id}/runs` | 分页、持久化状态与缺口提示；不提供任意文件读取 |
| 文件成果 | 历轮 `result.artifacts`、鉴权成果接口 | 路径、哈希、文本/图片检查与有基线的差异；不是任意文件下载或完整版本库 |
| 重启恢复 | serve 的清单与会话日志 | 会话可恢复，后台进程不会自动复活；在途轮次有中断标记 |

后续重点：

1. 将完整历史、历轮成果与侧栏投入真实任务试用，记录实际缺口。
2. 工作台如何与服务同源部署，并复用已有鉴权及 Host/Origin 校验。
3. 多工作目录的允许范围与会话归属，是否满足首轮两个项目的试用。

登记成果预览、受控文件浏览、差异与 Finder 定位已接入；读取受来源、范围和大小校验，
不能用前端任意路径读取来绕过接口。终端是用户明确打开的独立工作区，不是隐式模型权限。

## 实现纪律

- 工作台作为独立消费端，复用内核状态、审批、问答和事件契约。
- 在实验目录内开发；仅在真实接入遇到缺口时提出最小内核改动，并单独测试。
- 本机试用沿用 host 环境；页面、模型输出和工具结果按不可信内容渲染。
- Web 版本人工启动服务，关页面不等于停止任务；macOS 版本拥有服务，关闭工作台停止自身服务，退出应用停止全部服务。
  服务停止和机器休眠不承诺持续执行。
- 模拟数据必须标注，与真实连接分开；离线验收使用脚本模型，不消耗真实模型额度。
- 第一轮不做账号、多租户、云同步、插件市场、桌面自动化或自动任务唤醒。
- 工作台采用原生浏览器模块，不增加前端依赖；macOS 实验使用系统 AppKit 与 WebKit。

## 从终端接续同一会话

先在羽案打开工作目录，再使用包含本分支代码的 CLI：

```sh
xiaoyu connect --workspace /path/to/workspace
xiaoyu connect --workspace /path/to/workspace --session SESSION_ID --history
xiaoyu connect --workspace /path/to/workspace --session SESSION_ID --watch
xiaoyu connect --workspace /path/to/workspace --session SESSION_ID --prompt '继续完成这项工作'
```

`connect` 使用桌面已经持有的会话及执行服务；不复制历史、不另建 Agent，不直接打开会话日志。
普通 `xiaoyu resume` 继续复制历史创建新会话；羽案对终端历史可原地继续或另开分支。
`--status` 查看当前轮与待处理事项；插话和停止必须带刚观察到的 `--turn`，可用 `--instance`
约束服务实例；审批必须明确 `--decision allow` 或 `deny`，仅本次有效。
问答用 `--answer QUESTION_ID --answers-json JSON`；`-` 从标准输入读取明确答案。
回答排队不表示已被模型接纳，空闲时仍需明确提交继续任务。

CLI 输出逐行 JSON。写入前输出 `submission_key`，断线后不自动重发；可以用同一幂等键核对
任务与答案，插话和审批则先读取状态。退出监听不停止任务。应用退出后连接不可用。
本机配对核验当前用户和私有 socket 权限，令牌只驻内存，不写命令参数、地址或文件。
失去写锁或执行收尾无法确认时，该会话的新写入会被拒绝；停止、拒绝审批仍可用。
未知执行的所有权保留到服务进程退出，随后重启并核对已有成果，不自动重跑。


### 0.12.0 历史切片：连接与自动化底座

侧栏“连接”保存公开的 HTTP 或 stdio MCP 配置；选择已有会话后明确挂载并启动。
列表显示实际连接、工具声明、隔离状态与授权状态；声明变更需核对当前指纹后批准，
工具执行仍经过原有权限审批。运行中、后台成员未收尾或管理操作未结束时不可变更工具集。
停止连接和解除挂载分别操作；配置修改不暗中替换已挂载实例，需解除后重新挂载。
管理请求绑定目标会话、服务实例和配置版本，结果未知时先核对；重启不会自动挂载或重放。

授权采用公开客户端 OAuth，点击系统浏览器继续，完成后返回应用刷新状态并明确挂载。
授权凭据只驻本次服务内存，取消待完成授权和撤销当前授权分别操作。重启后须重新授权。
首版不接收 headers、env、token 或 client_secret 配置。stdio 命令与参数会明文保存，
不要填写密钥；无法完整自动识别参数中的秘密。应用复用仓库 SDK 的协议实现。

侧栏“自动化”可保存一次性或不少于 60 秒间隔的任务，选择工作目录、模型和提示。
保存后默认禁用，明确启用才开始调度；仅在当前应用服务运行时触发。错过的离线周期不补跑，
同一任务未结算时不再触发下一轮。每次触发先持久登记，再使用原执行服务创建会话与提交，
可进入关联会话处理审批、问答和查看成果。提交回执不确定时暂停后续触发，重启不自动重放。
人工核对不会把未知标成成功；关联会话仍活跃或无法确认时不能解除未知状态。确认后仍需
单独重新启用；没有关联会话的未知创建需根据核对说明人工确认，不假定先前提交失败。
退出应用即停止调度，不安装系统常驻服务。
