# 羽案：产品边界、协作交互与会话互通

2026-10-16。产品方向与开发边界；本轮实现更新至 0.12.14。逐切片交付与限制见 ITERATION.md，最终自动验证见 VALIDATION.md；手工原生、真实账号与真实模型验收仍待进行。

## 产品原则

羽案是基于 xiaoyu 的独立 GUI 产品，拥有自己的产品路线、应用数据和发布版本。
CLI/TUI 是另一个产品入口，围绕终端操作、脚本与管道发展。
两者共用执行事实和能力，不要求菜单、交互或功能清单一一对应。

由羽案首次提出、甚至长期只有羽案使用的底层服务，也可以属于 xiaoyu：
归属取决于执行语义和责任，而不是当前有几个消费者。
羽案可以先发展图形能力，再推动核心提供稳定接口；不要求先做成终端命令。

### 已确认的产品方向：完整桌面能力与导航预留

2026-10-16 用户确认：羽案按完整的综合桌面应用规划功能组织、导航层级和交互闭环，
持续补足不足。规划范围包括项目、作品、知识空间、能力扩展、自动化、
跨内容搜索和侧栏整理；每一项都落成羽案自身的产品需求。
羽案应能完成日常对话、内容创作、资料组织、工程执行和多智能体协作。
现有执行底座继续复用，GUI 产品线可以独立提出功能并推动核心接口迭代。

规划入口时区分导航预留、功能路由和实际可用菜单；预留入口只表示方向，
不能据此承诺羽案已经具备对应能力。

目标导航与当前缺口如下；具体版本和开发顺序统一维护在 [ITERATION.md](ITERATION.md)。
这些产品切片安排在 0.12.x，位于已完成的 0.12.0 底座与 0.13.0 发行工程之间；
0.13.0 继续聚焦独立运行环境、签名公证与更新。

| 入口 | 当前实现（0.12.14） | 仍需补齐的范围 |
|---|---|---|
| 新建任务 | 对话、创作、工程草稿及三种协作表单；直接输入建会话，模型/权限选择 | 主输入思考强度、语音与通用附件上传未接 |
| 搜索 | 有界索引检索登记会话原始正文、项目资料、作品、页面与空间，回到来源 | 不扫描任意磁盘，不承诺覆盖被截断或未登记的内容 |
| 项目 | 工作目录、项目指令、文本资料、会话与作品聚合、受控文件浏览 | 上下文需明确引用并提交；不是通用文件同步系统 |
| 作品 | 全局登记作品、筛选/收藏、来源、文本差异与 PNG/JPEG 安全预览 | 非完整版本库，无高级图像或办公文档编辑 |
| 自动化 | 一次性、固定间隔、按星期/时区的日历计划、运行历史与待处理 | 应用运行期间调度；无系统常驻或外部事件触发 |
| 能力 | 实际技能/插件清单、空闲技能重载、连接管理与协作模板 | 插件安装/升级/卸载 GUI 未接，保留核心 CLI 审阅入口 |
| 空间 | 空间与页面编辑、项目/作品引用、页面版本和单页导出 | 尚无内容库整库备份或办公格式导入 |
| 最近会话 | 分组、排序、未读、置顶/归档、重命名、历史分支与独立侧边会话 | 分支不回滚文件；同工作台的新视图共享执行者，不恢复旧进程 |
| 设置与更多 | 分类搜索、偏好、默认模型/模式、服务商、快捷键、实际用量、元数据备份 | 长期设置规划尚未全部实现，详见 SETTINGS.md |

图片、文档、网页等创作先作为作品类型和工作模板逐步补齐；具有完整独立流程后，
再考虑专项入口。七襄、斗巧、宸枢通过能力页的工作模板进入对应任务交互，
继续共享项目、会话和成果；不为展示入口另建隔离的执行体系。

用户允许部分未实现功能先在侧栏预留；作品、能力和空间现已接真实入口，不再仅作预留。
今后的预留项标注“规划中”，点击进入简短说明页，说明用途、当前可用替代入口和实现状态。
状态区分“规划中”“部分可用”“可用”；已有局部能力保持可访问。
预留页不展示虚构作品、运行记录或成功状态，不提供无效执行按钮；用户可以隐藏
预留项。尚未确定交付时间时不使用倒计时或发布日期承诺。
菜单预留完成只代表导航交付，功能闭环另行记录和验收。

### 主工作区、会话菜单与工具标签页

主窗口采用左侧导航、中央对话与输入区、按需展开的右侧工作区。右侧支持拖动调整
宽度、收起、放大与多个标签页；窄窗口切换单栏。新标签页提供网页、文件、页面、
终端与协作看板入口，未实现项明确预留。打开或关闭视图与启动或停止任务分别处理。

| 工作区内容 | 目标交互 | 执行与数据边界 |
|---|---|---|
| 网页 | 地址栏、前进/后退、刷新、多标签；选中内容引用到任务 | 手动浏览、模型读取、模型操作分别呈现；引用包含网址与采集时间。浏览器控制需有真实工具接口，展示网页不代表模型已能操作 |
| 文件 | 项目文件树、预览、选中内容引用、差异查看 | 区分当前文件和交付版本；写入经已有执行权限或明确的用户编辑保存路径 |
| 页面与作品 | 新建页面、编辑文本、图片与网页成果预览、版本和来源 | 保存关联项目/作品；外部网页与本地成果预览隔离，不共享应用管理桥 |
| 终端 | 真实交互式终端、工作目录与进程状态、输入输出 | 与 CLI 历史查看/导入分开；用户输入与模型命令来源可辨，模型执行继续使用原权限链。关闭标签页时说明进程去留，重启不伪造活进程恢复 |
| 协作 | 七襄任务表、斗巧方案比较、宸枢看板 | 展示同一执行服务的真实状态；标签页不另建执行者 |

右侧内容通过明确的“引用到任务”动作进入输入草稿，显示来源和选中范围，提交后才
送入模型；仅切换标签页不自动传送页面、文件或终端全部内容。关联到当前任务的操作
与成果能回到来源会话。网页运行容器、浏览器自动化和终端进程接口在实现前分别核对
平台能力与安全模型，不把已有文本工具输出包装成交互终端。

输入区集中项目/工作目录、资料引用、工作方式、权限模式和模型。直接输入可创建会话，
使用当前选定工作目录；不是无工作区的独立执行环境。思考强度选择、通用附件上传、
语音输入与实时语音尚未接入。开始页输入区居中，执行后置底，支持插话排队/接纳回执
及停止；未实现的录音能力不提供可用状态。

右上角会话菜单与侧栏右键菜单共用动作定义：重命名、置顶、侧边会话、历史分支、
创建自动化草稿、复制/导出、分享预留、新窗口及归档。侧边会话是独立讨论，分支复制
选定历史但不回退文件，会话菜单的新窗口观察同一会话并共用所属工作台执行者。自动化草稿需确认后启用；
归档不停止执行。已有动作接真实状态，其余分批交付并明确标注。

### 设置中心

设置中心是独立产品页面，包含分类搜索、应用偏好、模型与服务、权限、数据、集成和
诊断等管理能力。详细范围与状态规则维护在 [SETTINGS.md](SETTINGS.md)；现有连接
面板只覆盖其中一部分。0.12.2–0.12.14 已完成常用项整合；分类搜索不是逐设置行深链，
标签集合/浏览登录态不持久恢复，高级权限和其他未实现设置仍按规划单独标识。

## 分层与归属

| 层 | 职责 | 实施落点 |
|---|---|---|
| 执行内核 | 模型、上下文、工具、权限、沙箱、编排规则、用量、执行事件 | 复用现有 xiaoyu 内核 |
| 通用运行服务 | 会话身份与所有权、历史/状态查询、执行与审批入口、成果来源、恢复 | 优先扩展现有服务和 SDK 契约 |
| 羽案应用服务 | 项目工作空间、置顶/归档、搜索索引、跨会话待处理、成果目录、预览衍生物、草稿 | 先在桌面实验目录内独立模块组织 |
| 羽案 GUI 与系统集成 | 工作台、协作看板、方案对比、图形编辑、拖放、菜单、通知、窗口布局 | 现有 Web 界面和 macOS 宿主 |
| CLI/TUI 产品 | 参数、管道、终端命令、按键、文本呈现与脚本化管理 | 现有 cli/tui/keys/render 模块 |

具体判断：

- 影响正确执行、权限、恢复或不同入口对数据的理解：内核或运行服务。
- 为 GUI 提供组合查询、检索与工作组织，但不改变执行事实：羽案应用服务。
- 卡片布局、比较方式、预览位置：GUI；终端补全与按键：CLI/TUI。
- 成员状态、成果来源、裁决结果是共享事实；看板排列和折叠状态是产品状态。
- 用户在 GUI 作出的采纳、指令或审批决定应成为有来源的执行记录，不能只存在页面状态里。

这些首先是模块和责任划分，不要求立刻拆多个发行包或常驻进程。
羽案后端可以组合现有回环 REST 服务，复用鉴权，不另造执行循环或私有执行协议。
试验中的应用业务对象不立即进入顶层公开 API 冻结面。

## 已核实的能力与缺口

SDK 已有动态 MCP/OAuth、DAG 任务、任务句柄、取消/重试、预算、存储和恢复等能力。
应先评估复用和暴露方式，不能把桌面缺入口描述成内核完全没有能力。

SDK 的 DAG 任务、内核织造工具和后台 shell 各有身份与生命周期；
可以统一展示活动，但不直接混用它们的任务 ID、取消和恢复命令。
DAG 调度也不等于按日历触发的持久化定时服务。

0.2.0 已补齐完整历史、历轮成果读取、重启后结算恢复和原生草稿持久化。
0.2.1 增加当前工作目录范围内的 CLI 日志发现、只读查看、显式分支，
以及七襄结构化事件、持久化批次快照和只读任务表。
0.3.0 增加表单预览后直接执行、按存档资格选择续跑、来源关联与成果版本检查。
小文本交付快照随结算保存，原生可定位登记文件；不替代完整版本控制或成果验收。

## 三种协作能力的 GUI 产品线

在任务中提供“协作方式”，使用通俗名称和文化名称并列：
批量执行·七襄、方案比选·斗巧、统筹协作·宸枢。
共享项目、任务、待处理与成果，不建三个彼此隔离的应用。
既支持模型在任务中使用，也逐步支持用户通过表单明确配置和发起；
直接操作应调用同一套经过校验的领域命令，不靠拼接自然语言假装精确控制。

### 七襄：从长报告变成可操作的任务表

目标：导入任务项、选择执行规格与并发设置，逐项查看状态、结果、文件与续跑能力；
筛选未完成项，选择其中若干项继续。

已有批量执行、隔离、超时、存档、结果汇总和批量 resume。
0.2.1 已提供稳定批次/条目身份、结构化结果与事件；0.3.0 提供表单发起和选择续跑。
0.9.0 已接入精确 execution_id 的单项停止、定向补充和条目审批归属；
初始执行与自动续补身份分开，旧消息不会转投新一代，历史观察不冒充可控制的活实例。

### 斗巧：从判官结论变成方案比较工作台

目标：设置题目、席位模型与评价标准，同屏比较答案、成果和实际文件差异；
展示判官推荐与理由，允许用户采纳不同候选并继续修改。

已有独立席位、异构模型、隔离、判官与失败后保留候选的机制。
0.4.0 已接入结构化裁决、候选结果和独立人工采纳记录。“推荐胜者”“用户采纳”“应用文件改动”是不同动作；
选中候选不自动合并或写入工作区，复制会话也不会撤销已经发生的文件副作用。

### 宸枢：从命令序列变成工程协作看板

目标：查看 mission、scope、依赖、成员、发现、评审、差异及合并阻断原因。
0.5.0–0.8.0 已交付真实看板、精确成员交互、结构化编排、差异检查、受控合并和独立清理。

已有 mission/member 结构、磁盘审计、收养恢复与合并闸。
成员工具集不等同于主会话。0.6.0 的服务托管成员继承主会话执行模式，保留工作区
写入守卫，并把实际需要的审批交给宿主，标明成员与运行身份；独立 CLI 保留原行为。
GUI 定向补充消息提供排队、进入上下文、结束前未接纳的回执；原有文件邮箱仍没有
已读承诺，不能混用两种语义。
总枢在等待成员时被打断，只停止等待，成员仍可能继续执行；停止主会话当前轮次
不能显示成全队已经停止，界面须分别呈现总枢和成员的真实状态。
GUI 不提供强制 teardown；整队清理需独立预览与确认，有活跃成员、脏文件或未知状态时拒绝。
停止执行、保留成果、清理工作区分别设计和验收。

### 共同底座

内核已有部分结构化结果，优先从既有对象提供稳定视图；不解析 Notice 或报告文案造状态。
提供快照与增量事件、来源关联、真实终态、审批归属、成果引用和可恢复性说明。
子任务详情按需订阅，TUI 可继续只显示摘要。
存档失败会导致部分能力仅在内存有效，必须明确显示，不能一律承诺重启后可续跑。
事件用于更新界面，快照用于重连核对；不把实时事件缓冲当完整历史。

## CLI 与羽案的 session

建议目标：会话可互通、界面各自发展、同一会话只有一个执行所有者。
并行子任务仍由该执行所有者按既有编排规则管理，这与跨客户端单写者并不冲突。

### 当前事实

- 两端共用 SessionLog/load_messages，不需要重造消息格式。
- CLI 常规 resume 复制历史到新会话文件；具名会话另有同文件续写路径。
- 服务使用独立日志目录与清单，当前不会自动进入 CLI 默认历史列表。
- 普通 CLI 保留原日志语义；服务自 0.11.0 起要求状态目录和会话日志均持有真实独占锁，禁止无锁降级。
- 服务会持有已恢复会话的锁，空闲不代表可由另一进程直接接管。
- 会话消息恢复不等于运行进程恢复，也不等于所有子任务与附件自动完成迁移。

### 三个明确操作

| 操作 | 身份 | 用途 |
|---|---|---|
| 查看 | 原会话，不创建副本 | 两端查看历史、成果和状态 |
| 在另一端继续 | 同一逻辑会话，显式交接或连接同一服务 | 日常跨端工作，原端可继续观察 |
| 从这里另开分支 | 新会话，记录父会话和分支位置 | 尝试另一方案、使用另一个项目环境 |

“导入”用于旧格式、外部日志、其他安装环境等迁移场景。
同机日常查看和接续不应总是复制一份历史。
分支只隔离会话历史；文件是否隔离要另行选择工作目录或 worktree，并明确说明。

### 已落地的互通路径与保留边界

1. 聚合现有会话目录，先不搬迁日志；按受控索引 ID 查询，不向前端提供任意日志路径读取。
   支持统一发现、只读查看、“在这里继续”和“另开分支”，记录来源和可恢复内容。
   终端会话与应用会话同列一份清单；原地继续走具名会话的同文件续写，谁持有写锁谁写，
   被占用时只读并提供重试与分支两个出口。
2. 0.11.0 已提供严格所有权与恢复核对，同一 session 跨端操作连接同一执行服务。
   锁无法建立时拒绝新写入；未实现独立执行者之间的热交接，不能接管正在执行的工具——
   原地继续只接已正常结束的会话，交接点是写锁的释放与取得。
3. CLI 可独立运行，也可使用 `xiaoyu connect` 连接已有桌面运行服务。连接服务时两个界面共用一个执行者；
   不为普通 CLI 使用强制引入桌面服务。

保留或引用对话、计划、成果与必要配置，并检查工具、目录与模型能力差异。
不迁移一次性审批、临时放行、凭据和活进程；浏览器连接等运行资源需重新建立。
子任务档案与成果按能力逐项处理，无法迁移的内容明确显示，不做静默丢弃。
GUI 草稿、置顶、布局等保存在应用元数据里，不强塞进模型消息。
CLI 无法呈现的图形交互给出摘要、成果定位与在羽案打开的入口；
必须图形操作的步骤保持等待，不伪装完成，也不丢掉原始交互数据。

### 0.5.0：宸枢只读协作看板

### 0.6.0：成员交互与保留成果的停止

已接入精确到成员运行 ID 的定向消息和停止。消息先持久登记，再进入运行成员的输入

成员工具审批显示看板、成员、任务、运行 ID 与工作目录，只能单次允许或拒绝。
服务托管成员继承主会话执行模式，build 文件写入守卫不能被宿主允许绕过；CLI 的
默认成员路径保持兼容。主轮停止不取消成员审批，服务关闭则请求停止它拥有的成员。

GUI 展示操作过程与真实结局，保留各成员及旧运行草稿。幂等键与请求原文先落盘；
同名成员重启、断线重试和服务重启均不会把旧操作重放到新一代。历史观察保持只读。

### 0.7.0：结构化协作编排

已交付新建或明确采用当前目录的协作状态、任务范围与依赖规划、成员派遣及精确续跑。
预览展示实际参数与仓库状态，提交和审批后执行前重新核对；启动工具复用原审批链，

宿主协作通过独占归属锁防止相互接管；旧 CLI 不参与此协议，必须先结束原拥有者。
旧状态仍有运行成员且没有宿主协议标记时拒绝接管。应用重启只恢复历史观察，明确采用
后才建立新的运行实例；不自动复活旧线程。草稿与原提交键持久保留，回执未知不换键重发。

### 0.8.0：当前差异、受控合并与独立清理

已交付当前已拥有协作的任务差异查询，展示基础/目标提交、评审所盖提交、依赖与
阻断原因。差异使用固定提交读取，禁用外部 diff/textconv；截断明确标注，历史看板
不会为了查看而被接管。可执行不代表已预判无合并冲突。

合并先预览，再独立确认，进入原工具审批；审批后再次验证主工作区、目标提交、
评审与范围。失败时只有核实恢复原 HEAD 和工作状态后才报告已回滚。
“清理工作树并结束协作”是另外的整队操作，列出每棵工作树和未合并分支；分支及
档案保留。存在活跃成员、脏文件（含忽略文件）或未知状态时整次清理禁用，不提供
强制删除。删除失败保留路径和协作状态，报告实际结果，不复用普通停止按钮。
本阶段项目上下文与成果预览围绕这些真实工作流迭代。后续按产品原则建设独立功能
页面，并允许明确标注状态的菜单预留；预留不计作功能完成。

跨端同一 session 接续已在 0.11.0 落地；连接能力与自动化底座在 0.12.0 落地，
后续应用层切片复用同一 SDK 和核心执行者。

### 并行开发的分工边界

- 内核/运行服务：历史、结算、协作状态和操作契约；关键文件由单一负责人整合。
- 羽案应用服务：索引、草稿、项目映射和跨会话聚合，不绕开运行服务改执行记录。
- GUI：先按约定契约开发，再接真实服务；演示数据显式标注。
- 集成验收：脚本模型端到端、重启/断线/重复操作、真实任务试用。

依赖接口先明确字段与语义后再并行写代码；不同 agent 不同时改同一关键模块。
涉及会话、工具或权限的代码修改跑全量 unittest；本设计文档变更无需运行测试。

### 0.9.0：七襄单项交互与精确执行身份

每次初始执行和自动续补拥有独立 execution_id；档案 run_id 仍用于后续续跑，二者不混用。
单项补充明确区分 queued、accepted、not_consumed；单项停止等待该执行结算，保留已写文件，
不影响同批其他条目。审批展示条目、执行身份与实际工作目录，只提供单次允许或拒绝。
控制回执和执行事实持久保存；重启读取既有结果，不重放未知任务。历史损坏时禁止新消息，
仍允许精确停止，并明确标记停止回执未持久化。

### 归档对话删除

已归档页提供单条删除与全部删除。删除前确认标题或当前工作台的归档总数；搜索只筛选
显示，不改变全部删除的范围。确认时固定会话清单并校验归档状态修订号，列表变化后
重新选择，不自动扩大范围。正在执行或无法确认写入所有权的会话不能删除。

删除移除会话历史、恢复清单与归档元数据，保留项目文件。部分磁盘操作失败时显示已删除
数量并保留剩余项；网络中断后重新读取核对，不自动重试删除。

### 0.10.0：项目工作台与成果预览

项目说明保存在独立的应用状态里。只有明确选择放入输入框并提交，才进入模型上下文；
已有草稿可追加或替换。会话置顶和归档不删除历史、不停止运行，待处理与执行中入口仍
保留归档任务。项目页按准确会话与任务引用聚合已登记成果，不扫描目录猜测来源。

PNG/JPEG 预览复用安全文件读取和指纹校验，限制大小与尺寸；交付指纹匹配才显示交付
版本，修改后只显示当前版本，文件丢失不伪造历史图片。图片解码不支持 SVG、HTML、动画、
交错 PNG 或包含压缩配置块的 PNG。应用状态采用修订号核对，并保留冲突输入和未知回执。

### 0.11.0：同一执行服务与严格所有权

CLI 的 connect 入口经过同用户私有 socket 配对，直接观察或操作桌面已有会话，不复制
历史或另建执行者。普通 resume 和历史导入仍分别创建新会话分支。令牌只驻内存，终端
退出监听不中断任务，原键重试不会在重启后重放已记录任务。

服务状态目录和会话日志都要求真实独占锁；锁失败、文件被替换或记录不完整时禁止新
写入。已记录回执仍可读取；停止、拒绝审批和关闭继续可用。普通轮次确实结算后可以
继续；取消或委托异常后无法证明全部线程收尾时保留所有权直到进程退出，重启后先
核对成果。连接管理期间同样不能启动新轮次，未收尾的管理线程不能释放执行所有权。


### 0.12.0：应用连接与自动化任务

应用层负责连接配置、目标会话选择、授权交互和任务日程；SDK 提供 OAuth/MCP 协议，
core 继续拥有执行者、审批、工具调用和会话记录。连接管理只在主轮及后台成员空闲边界
修改工具集，管理线程未结束不得放开运行或关闭其池。服务实例改变使旧管理请求失效。
凭据仅内存保存，配置持久化不等于挂载，授权完成也不自动启动连接。

自动化采用持久触发身份和固定提交键，服务运行期间调度，先登记后执行；同任务未结算
不重叠，未知状态阻止后续触发。审批、问答、交付来自原会话真实记录。取消、失败、未知
分别显示，人工核对不冒充成功。核心锁丢失时应用元数据和自动化写入也停止，读取仍可用。
0.12.0 起提供一次性与固定间隔任务，0.12.10 补充按星期与 IANA 时区的日历计划；
系统常驻、连接凭据长期保管和独立发行仍不在本轮范围。

## 0.12.20 多工作台边界

“文件 → 新建工作台 / 打开文件夹”建立独立的目录范围与后台生命周期；“窗口 → 此工作台的新视图”仅增加观察同一工作台的窗口。关闭或重启一个工作台不影响其他目录。应用仍由统一原生协调器管理菜单与窗口，各工作台的核心服务进程独立。

窗口、会话位置和视图身份可恢复，主输入草稿按视图隔离，提交幂等保护仍属于工作台。恢复窗口不自动启动服务；点击恢复后才接入工作台及其已有自动化计划。详见 [多工作台设计](MULTI_WORKSPACE.md)。
