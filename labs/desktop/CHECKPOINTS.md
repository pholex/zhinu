## 后续提交节奏

1. 每轮开始核对所在分支和工作区，只纳入本轮确认的改动，保护其他未完成工作。
2. 完成相应验收后立即做本地提交；提交应包含匹配的实现、必要测试与文档。
3. 提交正文说明目的、验证命令与结果、已知限制，用户可见变化写入 `行为变化:`。
4. 交付时提供 commit ID。应用构建记录同时注明来源 commit 和是否含未提交源码，
   版本号、构建号与 commit 分开记录；不把旧安装包追认为新 commit 的构建产物。
5. 同一轮涉及多层联动时可作为一个完整提交；有独立验收边界时拆分，避免仅按文件类型拆散功能。
6. 验收失败时继续修复，或明确标注未完成及失败原因，不能记作已通过。

本地提交不包含 push、合并、发布或创建正式标签的授权。原有“暂不提交”仅作为历史
执行背景保留，后续以本节及根目录 `AGENTS.md` 为准。
