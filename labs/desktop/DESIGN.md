# 羽案界面规范

## 目的

让用户先看见工作内容，再找到下一步操作。功能、视觉与交互分别验收；
通过协议测试不能代替实屏检查。现有原生外壳和 WebKit 保留，不因视觉改造迁移框架。

## 面向用户的文案与选择

- 名称先回答“选了会发生什么”，内部模式名、协议字段和服务术语不直接作为常用入口文案。
- 有行为差异的选项采用图标、中文短名和一句结果说明；说明必须符合真实能力，不能为了简洁夸大权限或自动化程度。
- “默认”同时显示实际生效的选择；同一功能在输入区和设置页使用相同名称。
- 常用状态简洁，限制、原因和操作后果在相关操作位置说明，不以常驻脚注堆满输入区。

## 单一事实源

- `macos/DesktopCoordinator.swift`：工作台目录去重、全局菜单与窗口恢复；生命周期边界见 [多工作台设计](MULTI_WORKSPACE.md)。
- `web/view_state.mjs`：稳定视图身份对应的草稿隔离、旧版迁移与共享回执同步。

- `macos/ModelSetup.swift`：原生首启模型配置、钥匙串交互与羽毛品牌入口；服务商键名和型号由核心预设生成。
- `web/style.css`：色彩、字体层级、圆角、菜单、导航、消息与输入区。
- `web/view_history.mjs`：本窗口视图导航栈，不承载执行操作或会话存储。
- `web/model_picker.mjs`：原生选择值之上的模型与工作方式弹层，复用选择、键盘与边界行为。
- `web/execution_modes.mjs`：桌面权限名称、简短说明与图标；不改变服务提供的模式清单和权限规则。
- `web/ui.mjs`：共用线性图标、任务起点、输入区高度适配；不得引入服务状态。
- `web/settings.css`：设置布局、设置行和暗色主题；不得重复声明主输入区或菜单。
- `web/panes.css`：右侧工作区、标签、浏览器和终端。终端字符度量需要与其运行逻辑一致。

## 视觉语言

冷中性浅灰作为应用底色，白色作为内容面，蓝色表达选中、焦点和明确操作。
告警与失败颜色只表达真实状态，不用于装饰。暗色须同时调整文字、浮层与状态色。
采用系统中文字体，不依赖外网字体加载。

- 间距：4 / 8 / 12 / 16 / 24 / 32px。
- 圆角：6px 紧凑状态、8px 控件、12px 内容块、14–18px 浮层或输入容器。
- 字级：正文 13–15px、辅助 11–12px、页面标题 20px；首屏标题最多 30px。
- 列表：标题 13px / 20px，辅助 11px / 16px。图标 18px，统一 1.7px 描边。
- 主栏与右工作区标题栏均 48px。正文列宽受控，避免超宽文本。
- 不用字符符号代替主要导航图标；不让每个操作都成为同等重量的带框按钮。

## 导航层次

全局功能使用 52px 图标栏，项目与会话使用 228px 上下文侧栏；收起侧栏仍可切换全局功能。
图标栏、上下文侧栏、工作区分别使用 `--rail`、`--sidebar`、`--surface`，以三档底色区分，暗色保持同样层次。
设置页使用自己的分类侧栏，暂时隐藏会话列表，不修改用户保存的侧栏折叠偏好。
原生窗口标题栏依次为后退、前进、侧栏开关，统一 14pt 符号和 30×28pt 点击区域。
展开与收起使用同一侧栏符号；网页宿主保留界面内 18px 图标的展开/收起按钮。
前后导航仅恢复本窗口访问过的视图与最新草稿，无可返回目标时禁用，不重新加载页面或重放任务。
新跳转截断前进记录，服务连接变化清空导航栈；各窗口互不影响。
设置页切换自己的分类导航，工作台切换项目/会话导航；快捷键与原生按钮行为一致。
主要入口、会话操作、设置分类、工作区工具与标签均使用共享语义图标，
原生选择项保留文字，在选择器旁显示图标。只有图标的按钮必须有可访问名称和悬停提示。
所有菜单在窄列中保持可见，短标签不拆行；长名称省略并保留完整提示。

## 交互规则

新任务首屏仅保留品牌标记与一句提问，输入区固定在底部。
输入区上层为浅灰的项目与工作位置栏，下层为白色圆角输入面；边框与阴影保持克制。
附件和任务起点收入加号菜单，权限在左，模型与提交在右。工作位置未接入的环境明确禁用。
模型菜单向上打开，只列真实配置；已有会话保持原模型，长列表支持搜索和键盘选择。任务起点收进输入工具菜单，
只填草稿；任务必须显式发送。提示与输入工具栏分行，避免挤压模型选择。
输入高度随文字变化，上限 220px，超过后内部滚动；窗口宽度变化后重新测量。
管理操作放在会话菜单，协作启动放在协作菜单，错误与待处理事项仍就地显示。
锁定草稿时，输入与任务模板入口同时停用。未保存设置不能让本窗口的侧栏折叠在导航时失效。
菜单支持点击外部关闭与 Escape 返回触发器；控件必须有可见键盘焦点与可访问名称。

设置分类切换只改变视图，不隐式保存或丢弃输入。窄分栏使用分类选择器，
不把全部分类堆在设置正文上方。只读分类不显示无关保存区；有跨页未保存更改时保留入口。

减少动画偏好必须有效。不得以动效延迟输入响应、替换草稿或重置焦点。

## 验收场景

1. 1280×860：新任务、已有对话、审批/问答、设置、右侧工作区。
2. 820×600：主操作可见，无页面横向溢出，侧栏历史独立滚动。
3. 右工作区打开：主内容以自身容器宽度适配，不仅依赖窗口断点。
4. 浅色与暗色：文本、禁用状态、错误提示和浮层均可辨认。
5. 长输入、窗口缩放、分类切换、菜单 Escape、草稿与焦点保留。
6. 脚本模型提交与继续、审批或问答、结果读取、页面保存与引用。

截图用于评估层次与对齐；输入、切换与布局连续性必须通过实际交互核验。
并行开发先共享这套规范，主负责人检查整合后的完整窗口。

## 首次启动

首屏显示羽毛 Logo、模型服务列表与进入工作目录的操作。示例从主流程移至应用菜单。
检测结果只显示来源和状态；不回显、复制、持久化到偏好或注入网页任何密钥。
检测钥匙串不弹授权；用户启用时允许系统授权。新密钥使用安全输入框，保存到系统钥匙串。
“已启用”表示已配置，不代表联网验证。已有网关与自定义核心配置保留独立入口。
服务商别名和模型来自核心预设；默认模型必须属于已启用的服务商，工作台仍可切换。

### 新会话起点

输入栏只保留高频操作。了解项目、起草文档、比较方案是欢迎区的快捷起点，不作为常驻模板菜单；仅在新会话、草稿为空且可输入时显示。选择一次填入可编辑提示词，并使用对话工作方式；不自动发送，不追加到已有草稿，不更改模型或权限。输入后隐藏，清空后重新出现。

后续完整模板放在能力页：包含任务说明、待填信息、参考材料、工作模式和预期成果，支持用户保存复用；模型可推荐，权限沿用用户选择。

### 输入栏添加菜单

加号直接添加本次任务的参考内容：系统选择本地文件或文件夹、搜索并选择核心已发现的技能。参考文本直接粘贴到输入框，不另设重复入口。不跳到资料管理页。添加结果以可编辑引用写入输入框，沿用草稿恢复机制，发送前不读取所选文件正文，不自动执行技能。异步选择必须仍属于同一工作台、会话与目录；切换后不得写入另一任务。

工作方式选择在鼠标选择提交前保持菜单焦点；工作方式允许再次选择当前项，以便重新打开对应协作表单。模型选择继续只在改变值时保存。

工作方式只区分普通输入与实际的协作流程。原对话、创作、工程只是提示词模板，统一呈现为对话；旧设置与导航记录中的这三种值恢复为对话。切换工作方式不修改用户草稿，不自动填入提示词。

协作功能统一显示“批量执行”“方案比选”“统筹协作”。选择菜单复用权限选择的两行样式：图标与名称，下方一行简短用途说明。内部协议标识保持兼容；服务状态说明在展示时转换，用户草稿和结果正文不做文字替换。

输入栏环境条采用悬停预览方案：保留原高度，静止时透明底色、保留淡色项目名；精细指针悬停或键盘焦点进入时 140ms 展开，退出后延迟 250ms 淡出。菜单打开时保持完整显示，非默认协作方式保留可见。无悬停能力的设备沿用完整显示，减少动画设置继续生效。

## 工作模式与对话页面

批量执行、方案比选、统筹协作分别打开独立任务页。每页只呈现本模式的配置、记录与结果；空看板、普通对话占位、历轮结算和技术事件不混入任务页。审批、提问、错误和停止入口仍可见。顶部提供返回对话及工作方式切换，前进后退保存页面身份，模式草稿互不覆盖。普通对话只保留相关任务的入口，不重复堆放三类工作表单。

对话正文采用右侧深色用户气泡、无底色的回复正文，回复提供复制操作。历轮结算和技术事件收进“运行详情”。发送控件按空闲、提交中、执行中、请求停止切换视觉状态；执行中有补充文本时同时保留停止和发送补充入口。

输入区仍为纯文本 textarea。默认 Enter 发送，Shift+Enter、Alt+Enter 换行，中文输入法确认不触发发送；保留用户显式设置的组合键发送选项。字体使用原生系统字体与苹方，常规字重；默认 15px / 24px，并随外观字号设置缩放。占位文字仅降低对比度。

发送按键升级时，旧配置曾无区别保存组合键默认值，不能把它当作用户的主动选择。首次升级将旧配置解释为 Enter 发送，正常保存后以独立标记记录迁移完成；之后的主动修改继续保留。迁移标记不进入设置 JSON，保持旧应用的字段兼容性。


### 对话内容与过程（0.12.51）

普通对话页不重复显示项目/模型副标题、完成徽标或提交成功提示；消息本身是发送反馈。
工具过程位于该轮回答前，完成后默认折叠为耗时或工具数量一行，展开后按顺序呈现说明、工具名称、参数和结果。
长文本与 JSON 结果限高滚动并转义，不执行返回内容；无工具的短对话不增加过程入口。
错误、审批、问题、文件成果仍可见。底层事件、轮次结算移至会话“…”中的运行详情对话框。

已有普通会话可以选择下一轮的模型。选择先写入会话清单，当前回复不变；下一轮边界使用内核模型切换并记录实际变化。
连续选择在发送前只保留最后一个；首次默认选择不产生切换记录。固定助手配置仍保持绑定。
接口携带服务实例及之前的选择，防止旧窗口覆盖另一窗口的选择；写入失败不改变原选择。
默认模型偏好另外保存，供新会话使用。现有包保留用于视觉回滚，不覆盖用户数据。


### 运行态查询（0.12.52）

MCP、工具、技能与模型的真实状态归内核所有。`get_runtime_status` 读取当前会话内存，
供所有客户端共用；桌面仅将工具名称显示为“查看运行状态”，沿用对话中的折叠结果。
正常查询无需审批；连接缓存、已注册工具、本步模型可见工具和技能正文载入分别报告。
不会为回答当前能力而扫描配置、读取凭据或执行 shell；实际工具调用仍走原有审批。
查询不做健康探测，不会主动修复或重连。详情中的服务状态只能解释为最近已知状态。


### 窗口控件与退出顺序（0.12.54）

左右侧栏开关放在同一原生顶栏，分别采用左、右分隔图标。侧栏入口属于窗口布局，
不占用会话操作区域；浏览器访问时保留页面内入口。
正常退出先完成确认、保存和恢复记录归档，再关闭界面并停止服务，避免服务收尾期间
的轮询错误干扰用户。主动退出与意外断连分别处理，真实连接故障提示不被全局屏蔽。


## 0.12.55：右侧工作区保留主对话

右侧栏的常规入口始终打开分栏：主对话在左、工具在右。侧栏宽度最多为内容区域一半，随窗口缩小而收敛，不自动覆盖对话。用户可以拖动分隔线调整，宽度偏好继续保存。放大是当前打开期间的临时操作，按钮随状态显示放大或还原；收起后再次打开恢复分栏，旧的放大偏好不再影响新版本。对话内容和输入草稿继续留在原节点，打开侧栏不切换会话。


## 0.12.56：新标签页具有可见的生命周期

“新标签页”必须新增一个选中的标签，不能只切回入口画面。空白标签可以切换、关闭，保留各自的网址与 shell 选择；选择网页或终端后将空白标签替换为实际内容。已有内容继续保留，主对话不切换。标签过多时自动将选中项滚动到可见位置。


## 0.12.57：按用户习惯接受网址

用户输入域名即可打开网站，省略协议时自动补全 HTTPS，明确输入的 HTTP 地址照原样使用。新标签页与已打开网页的地址栏使用同一规则，不展示浏览器默认的英文格式错误。空输入和无效地址用中文说明；地址框提示“输入网址，如 baidu.com”，不暗示尚未提供的搜索功能。


## 0.12.58：输入框混排字体

主对话与侧边会话输入框优先使用 Monaco 显示英文、数字等字符，中文使用 PingFang SC，缺失字形由系统回退。沿用现有字号、字重与行高，保证中英文混排和编辑时的阅读体验。


## 0.12.59：左侧导航聚焦寻找与切换

导航的常驻内容是标题和层级：新对话、置顶、项目、最近。会话使用单行，项目归属通过所在分组体现，完整状态通过悬停补充；正常完成不重复占据第二行。异常、运行中和未读保留轻量提示。置顶和归档操作在行内悬停或键盘聚焦时显示，触控环境可直接访问。筛选集中在铃铛菜单，当前筛选结果始终有退出入口。分组可折叠，并在刷新期间保持状态。原有项目管理、项目详情、归档恢复和搜索继续可用。


## 新对话与输入缓存（0.12.60）

- 打开新对话、输入文字、选择项目目录不创建正式会话；首次发送才创建并提交。
- 未发送文字作为输入缓存：服务工作目录隔离存储，再按窗口身份与所选项目路径区分；返回新对话自动恢复，不加入最近、置顶、项目会话或搜索结果。
- 普通输入与模式配置可以分开准备。模式准备使用的空服务会话不写恢复清单；首次执行前仍可靠保存提交回执。已有执行、分支来源、失败或待处理操作不能当成空会话隐藏。
- 接收成功后仅清理来源目录中仍等于提交原文的缓存，不覆盖用户后来修改的内容或其他目录/窗口的缓存。
- 项目说明、成果和会话管理集中在项目设置；入口放在项目行悬停/聚焦显示的更多按钮，不混入会话列表。


## 项目与文件夹（0.12.61）

项目有独立身份和名称，组织多个会话；文件夹是项目关联的工作范围。项目可关联零到多个文件夹，非空时始终指定一个主文件夹。新对话默认从主文件夹开始执行；其他关联文件夹纳入该会话文件工具和命令沙箱的工作范围。附加文件夹不作为自动发现配置、指令或技能的新根目录。

项目创建、重命名、关联或移除文件夹均不创建会话，不移动或删除用户文件。无文件夹项目在首次执行时使用独立的应用工作目录。切换项目恢复该项目在当前窗口中的未发送草稿；同一文件夹关联到不同项目时不会共享草稿。旧版按路径存储的输入缓存只迁入匹配的默认项目一次。

会话记录稳定项目 ID 及创建时的目录快照。修改项目文件夹只影响新会话，已有会话及其分支恢复原工作范围；页面直接说明这一规则。项目文件浏览可选择各关联目录，目录外路径和符号链接逃逸仍受原有检查约束。自动化按项目身份绑定时，每次触发创建新会话并解析当时的主文件夹；表单与任务列表明确显示这一规则。保存时目录仅作配置快照，不限制未来触发。选择指定工作目录的任务仍固定使用该目录。创建会话被明确拒绝时记为失败并停用，修正配置后可直接重新启用；断连或不确定响应仍要求核对。

项目元数据从 workspace.json 首次复制到 projects-v2.json，旧文件原样保留；后续新版写入只更新新版文件。旧版可继续读取自己的快照，但不会读取新版新增的项目和修改。已创建会话的原执行目录不会因回滚而被改写。

## 归档对话

归档页以项目为组，组头显示项目名称和当前结果数量，对话行显示标题和更新时间。
搜索与项目筛选组合生效；同名项目按独立项目标识分组，未关联项目的记录集中在
“未分配项目”。无结果时保留筛选入口，允许直接切换项目或清空搜索。

行内主要操作为“取消归档”，删除使用垃圾桶图标，带悬停说明和可访问名称。
点击标题打开原对话，取消归档保留当前页面；单条及全部删除均沿用确认流程。
“全部删除”始终指当前工作台的全部归档对话，包括筛选之外的记录；悬停说明与
确认数量明确这一范围。分组及筛选不改变删除请求、会话内容或项目文件。

列表使用项目分组容器和内部细分隔线；窄面板下筛选和行内操作自动换行，避免
长标题挤出按钮。常态只显示每组数量，搜索或筛选时补充总匹配数量。
