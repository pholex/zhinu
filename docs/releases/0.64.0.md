# 0.64.0（2026-10-06）

自 v0.63.0 以来的变化。

## 新功能

- **`@c` 办不了的需求直接转给 `@x`**——`@c` 判定「不是一条命令能办的事」（要讲解、要总结、要分几步）时，以前只回一句说明，你得把同一句话再用 `@x` 敲一遍；开了 `--natural` 更别扭，敲一句中文有时得到命令、有时只得到一句「去用 `@x`」。现在集成脚本认出这种情形，把需求原样交给 `@x` 续会话、逐条审批。需求连同管道材料经配置目录下 `term/` 的私有文件交接，取走即删。
- **要看执行结果才能回答的需求，`@c` 也交给 `@x`**——真实模型对「本机有哪些网卡，分别干什么用的，讲讲」给了一条命令，还在说明里许诺「按输出逐条讲」，可 `@c` 看不到输出，这句承诺兑现不了。现在这类需求直接转走、不反问；只要输出本身的提问（看 ip、找大文件、列监听端口）照常给命令。
- **`@c` 给出的命令撞上你的别名时提示一行**——环境画像只看 `PATH`，不知道你把 `ipconfig` 定义成了跑别的东西的别名；模型给的命令是对的，回车后却走了别名。现在 zsh / bash 脚本在命令放上提示符之前查命令位置上的词，撞上「换了命令」的别名就提示改写成 `command xxx`。只给同名命令加参数的别名（`ls='ls -G'` 一类）不提示，函数不查；别名不发给模型。
- **会话有了可引用的 id，`resume` 认 id**——开场（含 resume 之后）打一行「接回本会话：`xiaoyu resume <id>`」，复制就能用。id 就是会话文件名，不另造一套；`sessions inspect` / `sessions export` 同样认它，可以把整场会话的完整记录交给别的工具分析。`resume` 的首个词长成 id 的样子就当作点名会话，找不到直接报错，不会退回去当成指令。
- **退出时再给一次接回命令**——开场那行在长会话里早就滚出屏幕了，退出时才是最想复制它的时候。一句话没说就退出的空会话不打。

## 修复

- **沙箱升权的确认框写明你在批什么**——bash 申请沙箱升权是 `--yolo` 下仍必问的三项之一，但两套确认框（交互界面与纯命令行）此前只画命令本身：按下「允许」时看到的是一条普通命令，并不知道批的其实是「这次不套沙箱」，模型给的理由也没有任何地方上屏。现在确认框写明档位、批下去的后果与模型给的理由，问句也变成「要升权执行这条命令吗？」。
- **`resume` 列表不再走进死胡同**——`@x` 的会话住在 `sessions/term/`，默认列表看不见，得加 `--all`；现在按归属目录一并列出。开了交互界面没说话就退出留下的空会话原来排在最前面，选中只得到「没有可恢复的消息」；现在默认不列，按名字仍能找到。

## 行为变化（升级前看一眼）

- **终端集成要开新终端才生效**——`@c` 转交 `@x` 与别名提示都在新版 shell 脚本里；已经开着的终端加载的还是旧脚本，`@c` 办不了的需求照旧只打一句说明，不会无声消失。
- **`resume` 默认列表变了**——本目录里 `@x` 过的对话会出现在列表里；空会话默认不列。
- **升权确认框多了两行**——档位、后果与模型理由，普通命令的确认框不变。
- **配置目录下 `term/` 多一种临时文件**——`@c` 转交 `@x` 时的需求交接文件，取走即删。

## 文档

- **README 安装一节重写**——直接推荐 `[tui,serve]`（已含核心，交互与 serve 是最常用的两项），五个可选组件按字母序点名（bedrock、browser、otel、sdk、serve），另给一条装全的完整命令（项目没有 `[all]`，以前得自己拼组件名，还容易漏掉 browser 要单独下载内核那一步）。升级与卸载命令单列成代码块。
- **澄清两个容易混的说法**——`[sdk]` 只带 jsonschema，单装它拿不到 SDK，嵌入要装独立的 `xiaoyu-agent-sdk` 包；`[browser]` 是 playwright 另起的 Chromium，和接管你登录态 Chrome 的浏览器扩展是两回事。

## 工程

- CLI 的 mcp / plugin / term 三族子命令拆成独立模块，按需导入，启动路径不为它们付代价；使用方式没有变化。
- 修了两个只在 Windows CI 上红的测试：会话解析断言按事件比路径对象，异步并发写入用例预留慢盘等待时间。
- ACP 注册表条目固定到 0.64.0。
