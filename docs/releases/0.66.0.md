# 0.66.0（2026-10-07）

自 v0.65.0 以来的变化。

## 新功能

- **SDK 新增 `AsyncSession.open`：异步创建会话，不阻塞事件循环**——`AsyncSession(options)` 的构造是同步的：打开存储、准备传输与 worker 都在调用线程上完成，在事件循环里直接构造会把循环停这么久（Windows 慢盘 CI 上实测 0.92 秒）。现在用 `async with await AsyncSession.open(options) as session:`：参数与错误同构造函数，同步部分放到自己的线程里做。创建途中被取消立即生效；setup 停不下来，已经建出来的会话会在后台关掉，不留存储锁和 worker——包括宿主取消后紧接着退出事件循环（`asyncio.run` 收尾）的情形。后台关闭若失败只记一条日志，不往线程外甩异常。`run_async` 内部已改用它；构造函数保留，现有代码不用动。
- **终端集成的 `@x` 收尾给出接回命令，`xiaoyu resume` 认具名会话的名字**——`@x` 开场打的是「会话 term-xxxx」，但以前照敲 `xiaoyu resume term-xxxx` 接不回：resume 只把「时间戳-pid」形状当会话 id，别的词一律当指令的第一个词，这个名字会被当成一句话发给当前目录最近的会话。现在 `@x` 跑成功后 stderr 多一行「接回本会话：xiaoyu resume term-xxxx」，resume 的位置参数命中具名会话（`--session-id` 起的、`term-…`）就是点名。接回写的是新文件，终端里的 `@x` 仍续原文件，两边从那一刻起各走各的。

## 行为变化（升级前看一眼）

- **`xiaoyu resume term-…` 找不到会话时报错，不再当指令发出去**——只对 `term-` 开头的词生效；别的词仍当指令，`xiaoyu resume fix the bug` 不会因为没有叫 fix 的会话被拒。
- **`@x` 成功后 stderr 多一行接回提示**——只走 stderr，不影响管道里的 stdout。
- **`AsyncSession.fork` 返回调用方的类型**——子类上调 `fork` 以前退化成基类实例。子类若在 `__init__` 里加状态，覆写 `_adopt` 类方法来初始化它（`open` 与 `fork` 都不经过构造函数）。

## 文档

- SDK 文档与 `examples/sdk/*.py` 里的异步示例改用 `await AsyncSession.open(...)`；API 表、存储契约与异步一节同步说明。

## 工程

- Windows CI 上两条偶发失败的用例已处理：MCP 迟到应答的用例等「迟到那条确实被读到」而不是固定 sleep，确认连接可用的那一步不再受 0.4 秒超时牵连；SDK 延迟提问的异步用例把只防卡死的等待上限由 3 秒放宽到 30 秒。
- 补一条用例钉住：`Session` 构造中段拿到 MCP pool 租约之后校验失败，租约随之退回，同一个 pool 还能再借出去。
- ACP 注册表条目固定到 0.66.0。
