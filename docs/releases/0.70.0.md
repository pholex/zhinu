# 0.70.0（2026-10-13）

自 v0.69.0 以来的变化。这一版只做一件事：serve 审批面的「本会话都允许」可以选更粗的一档，一次放开全部浏览器写操作。

## 新功能

- **`allow_session` 可选更粗的档位（`browser:*`）**——0.69.0 的会话级放行按单次调用推导范围：bash 推成命令键，桥工具推成工具名。浏览器桥七件写类工具（open / navigate / click / type / key / back / close）各是一个名字，一场会话要逐个点七次才能全放开。现在挂起项多一个 `session_scopes` 字段，细到粗列出可选档位（每项 `{scope, label}`，首项就是原来的 `session_scope`）；浏览器写类工具多出第二档 `browser:*`（文案「本会话全部浏览器操作」），`POST /session/{id}/permissions` 的 `allow_session` 带 `scope` 选它，之后本会话内所有 `browser_` 工具不再问，会话结束即失效。范围仍由服务端推导：粗档位只来自内核里的一张工具族表（目前只有浏览器一族），且必须随这次挂起项下发过——推不出细档就没有粗档，选了没下发的档位回 400 且挂起项不消费。`GET /permissions` 的 `granted.tools` 里记的就是 `browser:*`，`DELETE /session/{id}/permissions/granted/browser:*` 收回。读类桥工具本来免审，不受影响；TUI 与 ACP 的确认框也不变。xiaoyu-chrome 审批卡片上对应的按钮随扩展下一版发出。

## 行为变化（升级前看一眼）

- **HTTP 审批契约仍是加法扩展**——挂起项与 `permission.requested` 事件多 `session_scopes`；`POST /session/{id}/permissions` 多可选字段 `scope`。不带 `scope` 的 `allow_session` 行为与 0.69.0 完全一致，只认 `session_scope` 的旧客户端照常工作。
- **两种新 400**——`scope` 不在这次挂起项的 `session_scopes` 里；或 `scope` 配 `allow` / `deny` 用（它只配合 `allow_session`）。两种情况挂起项都还在，可以重新回决定。
