# 0.67.0（2026-10-07）

自 v0.66.0 以来的变化。这一版没有新的大件，是一轮健壮性与顺手程度的集中补强：三处口径不一致的修复、搜索工具的凭据保护、模型请求的两道新护栏、一批交互小件，以及发版与验证的工程脚手架。

## 修复

- **`hooks.toml` 认全内核实际触发的事件**——内核早已在委托子 agent 前后与压缩前后触发 `SubagentStart` / `SubagentEnd` / `BeforeCompact` / `AfterCompact`，SDK 文档也承诺命令钩子认同一组事件名，但 `hooks.toml` 的准入表只列了 7 个，照文档挂这四个事件会被拒「不认识」。现在补齐，并有一条测试对着源码里的触发字面量核对事件表，再漏直接红。
- **`xiaoyu resume` 跟随旧会话最后生效的模型与模式**——ACP `session/load` 与 `@x` 接回都按会话留痕恢复模型，`resume` 却用启动时的默认模型重建。上下文是按原模型长的，换模型接着聊应是显式选择：现在默认跟随，新加 `--model` 显式覆盖，`--mode` 显式给了同样优先。
- **无工具请求收到 tool_calls 时当场剥掉并给用户交代**——收尾、摘要这类不带工具的请求，模型偶尔仍回 tool_calls；以前照记入历史、靠下一轮补一条「已放弃」的假结果，用户这轮看不到任何说明。现在正文留着，没正文就补一句固定说明，并打一条提示；不再产生孤儿调用。
- **MCP 工具撞名按 NFKC + casefold 折叠后判定**——同 server 重名与跨 server 冲突预检以前只按原串比较，大小写 / 全角 / 组合字符的同形名绕得过去；现在折叠后再判，报错同时列出撞上的两个原始名。注册名不变。
- **grep 后端的输出、单文件体积与超时都有界**——以前结果整份读进内存、只有 60 秒一道界，宽泛 pattern 打在大仓库上内存先爆。现在 stdout 只保留前 8 MiB、超出即整树终止并提示收窄；超时先 SIGTERM 给宽限再 SIGKILL；rg 加 `--max-filesize 1M`，纯 Python 兜底同值。
- **Windows 保留设备名（CON / NUL.txt / COM1…）按名字拒读**——这类名字在任何目录、带任何扩展名都指向设备，stat 还报成普通文件。只在 Windows 生效。

## 新功能

- **搜索类工具跳过 `.env`、私钥、`.ssh` 等敏感文件**——`grep` / `list_files` 免确认、只读，正是沙箱明确不挡的那条凭据外泄路。现在命中的匹配行与文件整条剔除并在结果末尾说明跳过了几个；搜索起点本身是敏感路径（如 `~/.ssh`）直接拒绝。`read_file` 不在此列，它走审批。`XIAOYU_SEARCH_SENSITIVE=0` 关，已登记进护栏表，`--unguarded` 预设一并放开。
- **每次请求只带最新 N 张图**——用户贴的图刻意永不老化，但各家端点对单请求图片张数有硬上限，贴图多的长会话迟早撞上 400 且每次重发同样 400。现在出网时只带最新 N 张（默认 20，`XIAOYU_MAX_IMAGES_PER_REQUEST`，0 = 不限），更早的换成带序号的占位文本；会话历史不改。图片超限的 400 现在有专门的分类与提示。
- **首 chunk 独立看门狗**——`XIAOYU_FIRST_CHUNK_TIMEOUT`（默认 300 秒，0 = 关）：请求发出后等第一个流事件超过它就中止本次尝试，按瞬时错误走既有重试与降级链，报错点名是哪个设置触发。以前首 token 要等满 10 分钟的读超时才判死。实现上是收紧这次请求的读超时，所以看门狗生效时流内两个 chunk 之间的等待上限也是同一个数。
- **`task_output` 按字节 `offset` / `limit` 分段续读**——头尾快照看不到长日志的中段。给偏移就按字节切片并回 `next_offset`，偏移只推进到完整 UTF-8 字符边界；无参调用保持原快照行为。同一任务、同一偏移、状态都没变时提醒一句，免得模型原地轮询。
- **`read_file` 截断显示超过 2000 字符的单行**——minified JS、单行 JSON 一行就能吃掉整段预算。超长行截成前 2000 字符并说明还剩多少；截断过的行不算读过，整体覆盖前得用 `offset=行号 limit=1` 单读。
- **hook 的 stdout 有了两种去处**——`UserPromptSubmit` 放行时 stdout 首行紧跟本轮输入注入历史（与 `SessionStart` 同一条不可信通道）；所有事件都认 stdout 为 JSON 对象且含 `systemMessage` 的形态，那段文本只显示给用户，不进历史不进模型。
- **工作区技能目录按 git 根 → 工作区逐层扫**——monorepo 子目录里开会话也能拿到仓库根放的技能，越靠近工作区越优先；与项目指令文件同一套层链，沿用同一道信任门。
- **ACP 客户端收到技能命令**——建会话时的命令菜单列出技能（描述带 `[Skill]` 标记），与内建撞名的挂 `skill:<名>`，选中后附参数即按与 REPL 相同的规则展开。
- **`/rewind` 回退对话后把那一轮原话预填回输入行**——改两个字就能发，不必凭记忆重敲；明文 REPL 没有预填能力就把原话打出来。仅回文件不预填。
- **`/copy`、`/export`**——`/copy` 把最后一条回复复制到剪贴板（pbcopy / wl-copy / xclip / clip.exe，都没有就经 OSC 52 交给终端，tmux 里透传）；`/export [路径]` 把本会话就地导出成 Markdown，默认落在工作区 `xiaoyu-session-<id>.md`。
- **窗口标题带状态与会话名**——「<就绪 / 运行中 / 等审批 / 等输入> · <会话名或目录名> · xiaoyu」，开着几个标签也分得清哪个在等自己按键。
- **`XIAOYU_BELL` 增加桌面通知通道**——除 BEL 外认 `osc9`（iTerm2 / WezTerm / ghostty）、`osc777`、`osc99`（kitty）与 `auto`，文案带状态与会话名；tmux 里透传。
- **Ctrl-C 清掉的半截输入可用 Esc Esc 取回**——误按一下不必重打。
- **通用 provider 支持自定义请求 header**——`XIAOYU_PROVIDER_<NAME>_HEADERS=Name=value;Name2=${env:VAR}`，三条协议的 client 都带上；中转站要求 `Authorization: Bearer` 走 Anthropic 端点这类场景不再需要改代码。`config --show`、doctor 与诊断包只露 header 名字不露值。
- **`XIAOYU_MAX_OUTPUT_TOKENS`**——显式覆写单次输出上限，三条协议各自翻译；本地小模型与中转站限输出上限时不再 400。
- **`config --show --json`**——给脚本与宿主读的生效配置：默认模型、各模型路由画像（provider / 协议 / 鉴权形态只给布尔 / vision / tools / context_limit / effort 档位 / header 名）与功能开关；密钥值任何字段都不出现。
- **配置向导落盘前先对主模型探测一次**——key 贴错一位、端点少个 `/v1`，以前要等「已写入」之后第一轮对话才炸。探测失败问「仍要保存吗？」，默认不保存；`--no-probe` 跳过。

## 行为变化（升级前看一眼）

- **`grep` / `list_files` 默认过滤敏感文件**——结果里不再出现 `.env*`、`*.pem` / `*.key`、`id_*`、`.ssh/` / `.gnupg/` 内的文件，末尾会说明跳过了几个。确有需要用 `read_file`（走审批）或 `XIAOYU_SEARCH_SENSITIVE=0`。
- **`xiaoyu resume` 默认跟随旧会话的模型与模式**——以前用启动时的默认模型；要换模型接着聊写 `--model`。
- **交互前端轮末默认多打一行简版耗时**——只在该轮耗时 ≥ 5 秒时打（耗时 · 输出 tok/s），`XIAOYU_TURN_SUMMARY=0` 关；`-p` 单发与 json 输出不受影响。
- **配置向导默认会发一条最小请求探测主模型**——会出网、花一点点 token；离线填配置加 `--no-probe`。
- **无工具请求里的 tool_calls 不再入历史**——改为剥掉并提示；依赖下一轮「已放弃」占位的脚本（应该没有）会看到差异。
- **每次请求最多带 20 张图**——更早的图在出网时换成占位；会话文件与 `/context` 不变。
- **首 chunk 看门狗默认开（300 秒）**——以前等首 token 可到 10 分钟；慢思考模型首 token 常超 5 分钟的话调大或设 0。
- **hook 的 stdout 若是含 `systemMessage` 的 JSON，首行规则不再生效**——以前 `SessionStart` 钩子若恰好输出 JSON，首行会原样进历史。
