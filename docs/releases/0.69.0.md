# 0.69.0（2026-10-12）

自 v0.68.0 以来的变化。这一版补齐 serve 审批面的「本会话都允许」，顺带修终端集成在非 zsh 下的两处不顺手。

## 新功能

- **serve 审批面补「本会话都允许」**——TUI 确认框答 a、ACP 的 allow-session 早就落进会话授权，HTTP 审批却只有 allow / deny：浏览器侧栏跟着网页来回填字、点按钮，每一步都弹卡片，想少点只能重启 serve 换 `--approval allow_all`，可桥按会话绑定，重启就断了当前对话，而且 allow_all 对浏览器工具太粗。现在 `POST /session/{id}/permissions` 的 `decision` 多一档 `allow_session`：放行这次，并且本会话内同范围不再问，会话结束即失效。范围由服务端按挂起的那次调用推导（非命令类工具是工具名，bash 是命令键，与 TUI 同一口径），随挂起项的 `session_scope` 字段下发；客户端只能选档、带不进自定义范围，推不出范围的调用回 400。`GET /permissions` 多 `granted`（本会话已放开的）与只读 `rules`；`DELETE /session/{id}/permissions/granted/{name}` 收回。`permission.resolved` 事件在 `allow_session` 时带 `granted`。持久规则刻意不经 HTTP 写（serve 的 token 持有方可能在远端）。xiaoyu-chrome 侧栏配套的第三个按钮与「已放开」清单随扩展下一版发出。

## 修复

- **非 zsh 环境不再被 `--natural` 卡住**——`--natural` 靠包 zle 的回车键实现，只有 zsh 有；此前 bash / fish / PowerShell 带上它直接报错退出，照着别的平台抄来的那一行（或在 Windows 上顺手加的 `--natural`）就装不上，看起来像集成本身坏了。现在静默忽略：`term init` 渲染时丢掉，`install` 不再拦截，也不往非 zsh 的启动文件里写这个无效开关。
- **Windows 上 `term install` 认不出 shell 时直接给 PowerShell 命令**——原提示叫人去看 docs/terminal-integration.md，可 pip 装的用户本地没有 docs/。改为直接打印要在 PowerShell 里执行的三条命令（建 `$PROFILE`、追加接入行、立即加载），带上 `--name` / `--command-not-found`，并提醒 5.1 默认执行策略会拦 `$PROFILE`。`$PROFILE` 仍不由 install 代写：它的位置随 5.1 / 7 而变，从 Python 里看不出用户开的是哪一个。

## 行为变化（升级前看一眼）

- **HTTP 审批契约是加法扩展**——`POST /session/{id}/permissions` 的 `decision` 多一个合法值 `allow_session`；`GET /permissions` 多 `granted` / `rules` 两个字段；挂起项与 `permission.requested` 事件多 `session_scope`；`permission.resolved` 的 `decision` 可能是 `allow_session`（另带 `granted`）；新增 `DELETE /session/{id}/permissions/granted/{name}`。只认 allow / deny 的旧客户端照常工作，按 OpenAPI 导入的工具清单会多出 `revoke_session_grant`。
- **`allow_session` 与 `updated_args` 同给是 400**——会话授权按原调用推导范围，改写过的调用只能 `allow`。
- **非 zsh 下 `--natural` 从报错变为静默忽略**——以前靠这个报错发现自己抄错平台命令的人，现在看不到提示了。
