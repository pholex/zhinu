# 0.63.0（2026-10-05）

自 v0.62.0 以来的变化。

## 新功能

- **`@c`：一句话换一条命令，放回你自己的提示符（zsh / bash）**——`@x` 的命令跑在小羽的子进程里，`cd`、`export`、激活 venv、`ssh`、`sudo`、交互程序都落不到你自己的 shell 上，也不进历史。`@c 找出大于 100M 的文件，按大小倒序` 只把这句话翻成一条命令：zsh 里它直接出现在下一个提示符上，可以改，回车才执行；bash 里它被打出来并推进历史，按一次 ↑ 取用。可以追问（`@c 只看 .log`），回车执行过的命令照常被记下，接着用 `@x 为什么失败` 是通的。不是一条命令能办的事（闲聊、要讲解、信息不够）它只回一句说明，提示符上什么都不放。默认用辅助模型（`XIAOYU_SUMMARY_MODEL`）、推理深度 `low`，通常一两秒；`@c --model … --effort …` 可改。见 `docs/terminal-integration.md`。
- **本机环境只探一次**——BSD 与 GNU 的 `sed -i`、`date -d`、`stat` 写法不同，是命令给错的头号原因。第一次 `@c` 时探一遍本机（系统与版本、架构、shell 与版本、基础命令是 BSD / GNU / BusyBox 哪一套、包管理器、常用工具装没装）并记到 `<配置目录>/term/environment-<shell>.json`，之后直接读；系统或 shell 版本变了、或过了 7 天再重探。
- **`@c` 每次带上会话处境**——是不是 root（不是的话有没有 `sudo`）、是不是 SSH 进来的会话、是不是在容器里。这三件事同一台机器上也会变，所以每次现读、不进上面那份记录：已经是 root 不加 `sudo`，没有 `sudo` 时给 root 下能直接跑的写法并说明要换 root 来跑；SSH 会话里会提醒碰不到你本机的剪贴板与图形界面；容器里不给 `systemctl`。只说是与否，不带用户名和主机名。
- **`term init zsh --natural`：不敲 `@c` 直接输入一句话**——默认不开，只有 zsh。开了之后在提示符上直接敲一句话回车，它在 shell 解析之前被改写成 `@c -- '原文'` 再照常提交；改写后的行留在屏幕与历史里，整句进了单引号，里面的 `;` `|` `$HOME` 都不会被 shell 解释。只有整行含非 ASCII 字符、且第一个词不是任何命令 / 别名 / 函数 / 目录、也不带 shell 语法字符时才转走——真命令永远照常执行；以命令名开头的句子（`git 怎么回滚`）与纯英文句子转不走，仍要写 `@c`。

## 行为变化（升级前看一眼）

- **`@c` 给的命令不过审批**——它由你自己回车执行，小羽的权限判定与沙箱都不参与，放上提示符的命令请照常看一眼。能认出来的强制删除（`rm -f` / `-rf`）与提权（`sudo` 等）会多打一行提示，认不出来不代表安全。
- **终端集成要开新终端才生效**——已经开着的终端里加载的还是旧版脚本，没有 `@c`。
- **`@c` 这个名字被占用了**——zsh 里是别名、bash 里是函数；你自己定义过同名的别名或函数的话，`term init` 的那一行排在后面就会顶掉它。fish 与 PowerShell 这一版没有 `@c`。
- **`--natural` 会包一层回车键**（zsh 的 `accept-line`）——原来的 `accept-line` 留在调用链上，先于或后于它包回车键的东西照常被调到，但没有拿真实的第三方 zsh 插件逐个验证过。开了之后回车行为不对，先关掉它排查：当前终端里 `zle -A __xiaoyu_term_natural_next accept-line`。
- **`<配置目录>/term/` 下多了两种文件**——`environment-<shell>.json`（本机环境）与 `<会话id>.recall`（这个终端最近 4 次 `@c` 的需求与命令，原文，30 分钟后不再带给模型）。
- **`@c` 发给模型的内容**——本机环境、当前目录、会话处境、最近 12 条命令（脱敏后；只看不取，仍留给下一次 `@x`）、最近几次 `@c`、你的需求，以及管道内容（有的话，最多 16000 字符）。`@c …` 这一行自己不记进命令历史文件。
