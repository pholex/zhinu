# 0.61.0（2026-10-02）

自 v0.60.0 以来的变化。

## 新功能

- **serve：装了 Chrome 扩展就能连**——扩展的 origin 默认放行 CORS，填地址和 token 即可使用；`--no-cors-extensions` 可关闭，本机无 token 的访问仍只认显式白名单。
- **模型输出畸形容错加固（八项）**——隐形字符、双向控制符、畸变的工具名、重复 id、空回复、截断指引、超限识别、schema 消毒，模型或外部输入给出畸形内容时既不中招，也不白费一轮。
- **让模型更"知情"**——余量提示、子目录约定懒加载、验收目标核对、网关 Claude 缓存断点，模型能主动收尾、按约定加载文件、核对验收目标；这些提示走 operator 通道或工具结果尾部，system prompt 只加一句静态指引，前缀缓存不受影响。
- **hooks 与技能增强**——hooks.toml 支持 `on_failure`（钩子超时 / 起不来 / 异常退出时按拦截或放行处理）、工具事件带 `call_id`（`ToolFailed` 顺带带上参数与输出），并新增 `SessionStart` / `SessionEnd` / `ToolFailed` 三个事件；技能支持参数占位，可用 `/<技能名>` 直接展开并看到支持文件清单。
- **MCP 更可控、更好排查**——每个 server 可限定 tools 名单（名单外的工具不注册，也不会因描述变化隔离整代），可指定启动 cwd；启动失败 / 进程退出 / 重连耗尽 / 手动重连失败的报错都附日志尾部；审批框新增「以后都拒绝」（ACP 面为 reject-always）；progress 与 message 通知可上屏；新增 `xiaoyu mcp probe` 做无脚本握手、列工具并打印 serverInfo 与能力，`xiaoyu mcp add` 支持 `--cwd` / `--tools`。
- **终端礼仪**——`XIAOYU_BELL=1` 时在一轮结束或等审批时响铃；窗口标题显示「xiaoyu · 目录名」，退出时还原；`XIAOYU_STATUS_HOOK` 在切到等待输入 / 等待审批时执行自定义命令（超时与失败静默）。
- **OpenTelemetry 导出**——设置标准的 `OTEL_EXPORTER_OTLP_ENDPOINT` 等变量，就能把每一轮、每次模型调用、每次工具调用按 GenAI 语义约定打成 span 推到自己的 collector；不设置就完全不启用，连 opentelemetry 包都不导入；消息内容默认不采集，开启采集时先脱敏再截断到 4 KB；导出不阻塞主循环，collector 不可达也不影响退出（可选依赖 `[otel]`）。
- **shell 集成：`xiaoyu term`**——不进 REPL，直接在自己的 shell 里 `@x 问题` 提问，自动带上刚跑过的命令、续写同一段会话；`xiaoyu term init bash|zsh|fish|powershell` 输出集成脚本，命令钩子只用 shell 内建追加一行，不起 Python 进程。
- **评测接入 harbor**——可在 terminal-bench 任务容器里跑横评，提供 run / list / show / task / compare / rm 子命令。

- **CLI 新面**——`/goal` 与 `--goal` 设一句验收判据，模型收尾前会先核对；`--stats` 在收尾用量行追加耗时、首 token 延迟与输出速度；`xiaoyu doctor --bundle` 一键打包诊断（doctor 结果、脱敏配置、会话尾部、崩溃文件，含路径与命令历史，分享前自查）、`--probe` 对默认模型发一条最小真实请求；`xiaoyu sessions export|rename`；`xiaoyu completion bash|zsh|fish`；`xiaoyu serve --tls-cert/--tls-key`。

## 行为变化（升级前看一眼）

- **命令入口改为 `xiaoyu.__main__:main`**——`term log` / `term info` 走快路径，不再导入整个 CLI。pip 升级会重写 wrapper；可编辑安装（`pip install -e .`）的要重装一次 wrapper 才走快路径，不重装功能也正常。
- **嵌入事件多了字段**——`RequestStarted` 带 `provider`，`RequestEnded` 带 `duration_ms` / `ttft_ms` / `usage` / `model` / `response_id` / `finish_reason` / `error`；都是加字段，老消费方不受影响。
- **HTTP 413 归为上下文超限**——此前按 fatal 处理，现在与其它超限一样触发压缩重试。
- **空回复不再写进历史**——无正文无工具调用的模型回复只记事件，严格的端点不会再因空 assistant 轮 400。
- **hooks.toml 的 PreToolUse 多了 `on_failure`**——默认仍是 allow（钩子失败放行并告警），设 `block` 才改为拒绝。
- **CI 装 `[otel]` 可选依赖**——运行期核心依赖仍是 4 个。

## 修复

- **MCP 的 Streamable HTTP 不再跟随重定向**——此前遇到 30x 会把 Authorization、Mcp-Session-Id 等请求头原样带到新地址，配置里写死的静态凭据会被带到第三方；现在直接报错并给出目标地址，提示把 url 改成最终地址。
- **plan mode 下能正常提交结构化结果**——`-p --mode plan --output-schema` 之前把提交结果当成写操作拦下，无人值守时退不出 plan mode、永远交不出结果；现在放行（结果只存内存，不碰现场）。
